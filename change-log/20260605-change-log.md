# 2026-06-05 变更记录

## 普通对话关系与亲密策略

- 普通对话导演增加更细的关系阶段判断：陌生、初识、朋友、好朋友 / 暧昧对象、伴侣。
- 直接表白不再允许几轮内快速固化为恋人承诺，避免角色过早输出“我爱你”这类长期关系承诺。
- 暧昧阶段会更自然地降速承接，不再在没有高压或越界的情况下突然打断氛围。
- 伴侣关系确认后，角色会更亲密而不是更保守；低压力亲密邀请可被温暖接受并协商节奏。
- 对不熟悉但安全的亲密玩法，角色会保留自己的喜好，同时表达愿意慢慢学、慢慢接受、按双方节奏试试看。
- 这些规则不写死角色名，而是由导演根据角色设定中的开放、谨慎、害羞、外向、冒险等特征安排不同表现。

## 普通回复重复控制

- 导演 `expression_policy` 增加近邻复读控制，要求避开上一轮开头、结尾短句、固定承诺句和高度相似表达。
- 语音回复专用提示词同步增加复读控制，避免连续多次说“我在这里陪着你”这类原地踏步内容。
- 用户只是回复“好 / 嗯 / 可以 / 知道了”时，角色需要给出小推进、轻微转移话题或更容易接话的下一拍。
- 如果用户明确要求“复述 / 照着说 / 原话说 / 重复这句”，系统仍允许按用户要求重复指定内容。
- 已用紫悦普通对话复现测试：普通承接不会重复原句，明确要求原话重复时可以照做。

## 普通语音回复质量

- 语音回复输出合同强化：亲密邀请场景下，至少一个语音句子必须包含角色当前可接受的具体动作短语。
- 修复普通语音回复额外冒出文本气泡的问题，语音步骤只输出 voice 段落 JSON。
- 语音回复继续继承导演给出的语言策略，减少中文 / 英文场景下括号、情绪提示和 TTS 语言不一致的问题。
- 语音情绪提示继续限制为语速、停顿、能量、重音和语调，不允许改变角色原本音色。

## 角色档案与角色设定合并

- 后端聊天链路明确以 `characters.prompt` 作为角色核心设定来源。
- `characters.data.prompt` 不再作为后端聊天设定来源，避免同一角色设定存在两份互相漂移的副本。
- API 和客户端仍保留可见的顶层 `prompt` 字段，用户无感知；后端组装消息时使用规范化后的顶层字段。
- 角色档案块继续注入到详细设定前面，包含名称、个性签名、性别、种族、16 人格、性格、兴趣和简介。
- System 官方角色设定文本中的年龄信息已移除，年龄改由角色档案字段接管。
- 生产库已迁移清理 `characters.data.prompt` 冗余副本，并保留迁移前备份。

## 摘要与记忆人称修复

- 普通对话上下文摘要现在会注入角色档案参考，帮助摘要模型识别角色身份、物种、性格基调和正确人称。
- 角色档案参考被明确标记为“只用于角色身份”，不得当成用户说过的话或对话中发生的事实。
- 摘要对话标签改为用户侧继续使用稳定占位符 `{{USER}}`，角色侧使用真实角色名，例如 `{{USER}}: ...` / `紫悦: ...`。
- 摘要正文要求继续使用 `{{USER}}` 指代用户本人，避免用户改昵称后角色认不得同一个用户。
- 摘要落库前增加用户名归一化；如果模型偶尔写出真实用户名，也会收敛回 `{{USER}}`。
- 手动摘要接口和自动摘要器都接入同样的角色档案参考与占位符归一化逻辑。

## Android 角色主页与系统 UI

- Android 角色主页继续补齐公开档案展示，增强角色简介、角色档案、相册和角色管理入口。
- 角色编辑页支持更多主页档案字段，并同步保存到后端公开资料。
- 角色列表、角色大厅、已发布角色页和设置页继续统一顶部栏风格。
- 系统导航栏颜色适配浅色 / 深色模式，减少底部导航区域与页面背景割裂。
- 记忆页面和聊天脚手架调整布局，降低输入区、键盘和内容区域互相遮挡的概率。
