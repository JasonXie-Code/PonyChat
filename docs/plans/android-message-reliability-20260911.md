# Android 消息可靠性检查与优化方案

日期：2026-09-11。用户问题：发送后立即锁屏，消息发不出或收不到，并出现 SocketException。验收环境按用户要求使用模拟器。

## 当前结论

截图只能证明连接中止，不能单凭截图断定服务端没有收到消息。代码中发现了可解释此问题的明确缺陷，先修复传输恢复路径；不能据此宣称已经达到 QQ 的全部可靠性。

| 环节 | 当前实现与发现 | 本次处理 |
| --- | --- | --- |
| 普通模式发消息 | ChatRepository 将 IOException 转成 ChatDelta.Error，绕开 ViewModel 的传输重试和 accepted 后补收分支 | 保留 IOException；408/502/503/504 按传输故障处理，429/业务拒绝仍走业务处理 |
| 延迟重试 | 重试任务只检查模式与 isStreaming，可能在新轮次、角色或会话切换后执行旧请求 | 独立 Job，绑定用户名、角色、会话及发起轮次；新轮次/重置/完成取消旧重试，沿用原消息 ID |
| 流结束 | 收到部分段落后，无 DONE 的流结束被直接当作完成 | 转入补收；业务错误作为终止状态，避免再进入流结束恢复 |
| WebSocket 健康 | ping 入队也更新 lastRxAt；断链回调没有立即终止保活等待 | 只以真实接收更新活跃时间；使用单调时钟；关闭/失败尽快进入重连 |
| 服务端断线续跑 | live_turn 用独立任务、shield、订阅回放；android_normal_accept 在响应消费前启动后台任务 | 已存在，不能重复建设或因断线取消生成 |
| 锁屏存活 | 已有 ConnectionService、前台通知、唤醒锁、网络恢复/解锁补拉 | 不再盲目加长唤醒锁；这些机制不等于进程永远存活 |

## 达到长期稳定还需补齐的机制

### 1. 持久发送队列与服务端持久幂等

目前未确认有独立、事务化、跨进程恢复的客户端待发队列。普通模式未确认消息依赖 ViewModel 集合，现有会话缓存不能替代 outbox。

建议使用 Room/SQLite：点击发送先事务落盘，再交给独立发送器；主键包含账号与 client_message_id，保存角色、会话、原始请求、附件状态、重试次数和下次重试时间。状态分为待发送、发送中、服务端已接收、确定失败；连接断开属于状态未知，不能直接标记业务失败。WorkManager 负责进程重建后的补偿，前台发送器负责即时性。注销、切换账号、删除/重置会话须有明确队列归属和取消规则。

服务端 LiveTurn 的完成回放缓存目前是内存级、每个账号/角色最近任务，受 5 分钟与 64 项限制。长期离线后或服务端重启后重试，不能只依赖该缓存保证不重复生成。应补数据库唯一键、接收回执和任务状态；重试同 ID 返回同一回执/任务，不能重新扣费或生成。应先完成这层，再启用无限期跨进程自动重发。

### 2. 持久接收、补洞和 ACK

现有 WebSocket 与 HTTP undelivered 支持离线补拉，历史接口支持序号和指定 message_id 补洞。完整可靠链路应为：消息持久化到本机 → 更新连续同步游标 → ACK → 通知/UI。需要审计当前内存去重、异步 UI 事件与服务端 ACK 的先后关系，覆盖“ACK 后应用被杀”的窗口。

游标必须表示连续已收到的位置，不能只保存最大序号；多角色、语音/图片延迟发布时可能出现序号空洞。推送通知只是唤醒提示，消息正文及附件以可重放的服务端存储为准。

### 3. 系统推送

当前 Android 源码未发现 FCM 或手机厂商推送接入。长锁屏、Doze、应用进程被系统回收，无法仅靠自建长连接保证即时通知。需要按发行设备接入厂商通道/FCM，并实现 token 更新、账号设备解绑、送达监测及去重。厂商通道需要对应应用配置和凭据；模拟器不能证明小米、华为等系统的真实到达率。

Android 官方说明 Doze 会限制网络和普通后台任务，高优先级 FCM 可为面向用户的消息提供短暂唤醒和网络机会：https://developer.android.com/training/monitoring-device-state/doze-standby

### 4. 可观测性与验收口径

按同一 client_message_id 记录客户端落盘、首次发起、服务端接收、生成完成、正文落盘、设备接收和展示时间。不要在诊断日志输出聊天正文或 token。

验收矩阵应包含：确认前断线、确认后断线、部分回复后断线、网关超时、网络恢复、连续发消息、锁屏/解锁、Activity 重建、进程回收、服务端重启、账号切换、重复 ACK、乱序补洞以及图片/语音附件。统计丢失数、重复数、恢复耗时和失败分类。模拟故障数据与真实生产表现分别记录。
