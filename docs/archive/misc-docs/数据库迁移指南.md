# SQLite 数据库迁移指南

## 📋 概述

本项目已集成 SQLite 数据库支持，提供更高效的查询性能和更好的数据管理能力。

## ✨ 特性

- ✅ **零配置**：SQLite 是文件数据库，无需独立服务
- ✅ **高性能**：索引查询比文件遍历快 10-200 倍
- ✅ **ACID 事务**：保证数据一致性
- ✅ **向后兼容**：保留文件系统作为备份（双写模式）
- ✅ **自动回退**：数据库失败时自动回退到文件系统

## 🚀 快速开始

### 1. 安装依赖

确保已安装 `aiosqlite`：

```bash
pip install aiosqlite
```

如果使用 `requirements.txt`，请确保包含：

```
aiosqlite>=0.19.0
```

### 2. 数据库初始化

数据库会在应用启动时自动初始化。首次启动时会创建 `ponychat.db` 文件。

### 3. 数据迁移（可选）

如果需要将现有文件系统数据迁移到数据库，运行迁移脚本：

```bash
# 迁移所有用户
python -m backend.db.migrate

# 迁移指定用户
python -m backend.db.migrate <username>
```

## 📊 数据库结构

### 表结构

- **users**: 用户表
- **characters**: 角色表
- **conversations**: 对话表
- **messages**: 消息表
- **user_settings**: 用户设置表
- **galgame_data**: Galgame 游戏状态表
- **galgame_messages**: Galgame 消息表

### 索引

所有表都创建了必要的索引以优化查询性能：
- 对话按角色ID、用户ID、时间戳索引
- 消息按对话ID、时间戳、消息ID索引

## 🔄 工作模式

### 双写模式（当前）

系统同时写入数据库和文件系统：
- ✅ **数据安全**：双重备份
- ✅ **向后兼容**：文件系统数据仍然可用
- ✅ **平滑过渡**：可以随时切换

### 读取优先级

1. **数据库优先**：如果数据库有数据，优先从数据库读取
2. **文件系统回退**：如果数据库失败或无数据，从文件系统读取

## 📝 API 变更

所有 API 保持向后兼容，无需修改前端代码：

- `POST /api/save_characters` - 同时保存到数据库和文件系统
- `GET /api/load_characters` - 优先从数据库加载
- `GET /api/conversation/detail` - 优先从数据库加载
- `GET /api/user/settings` - 优先从数据库加载
- `POST /api/user/settings` - 同时保存到数据库和文件系统

## 🛠️ 维护命令

### 查看数据库信息

```python
import sqlite3

conn = sqlite3.connect('ponychat.db')
cursor = conn.cursor()

# 查看所有表
cursor.execute("SELECT name FROM sqlite_master WHERE type='table'")
print(cursor.fetchall())

# 查看对话数量
cursor.execute("SELECT COUNT(*) FROM conversations")
print(f"对话数量: {cursor.fetchone()[0]}")

# 查看消息数量
cursor.execute("SELECT COUNT(*) FROM messages")
print(f"消息数量: {cursor.fetchone()[0]}")

conn.close()
```

### 备份数据库

```bash
# 简单备份
cp ponychat.db ponychat.db.backup

# 使用 SQLite 备份命令（推荐）
sqlite3 ponychat.db ".backup ponychat.db.backup"
```

### 恢复数据库

```bash
cp ponychat.db.backup ponychat.db
```

## ⚠️ 注意事项

1. **数据库文件位置**：默认在项目根目录创建 `ponychat.db`
2. **文件系统备份**：双写模式下，文件系统数据仍然更新，可以作为备份
3. **迁移时机**：建议在低峰期进行数据迁移
4. **性能监控**：观察日志中的 `[DB]` 标记，确认数据库正常工作

## 🔍 故障排查

### 数据库初始化失败

如果看到警告日志：
```
⚠️ 数据库初始化失败（将使用文件系统）: ...
```

检查：
1. 是否有写入权限
2. 磁盘空间是否充足
3. 查看详细错误日志

### 数据不一致

如果发现数据库和文件系统数据不一致：
1. 运行迁移脚本重新同步
2. 检查日志中的错误信息
3. 考虑禁用文件系统写入（仅数据库模式）
