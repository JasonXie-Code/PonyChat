# 仅数据库模式说明

## ✅ 已完成的修改

### 1. 配置项
- ✅ 在 `backend/config.py` 中添加 `DISABLE_FILESYSTEM = True`
- ✅ 导出配置项供其他模块使用

### 2. 路由修改

#### `save_characters` (POST /api/save_characters)
- ✅ 禁用文件系统时，仅保存到数据库
- ✅ 保留头像文件保存（前端需要访问）
- ✅ 数据库删除逻辑：删除前端已移除的对话
- ✅ 数据库失败时抛出错误（不再回退到文件系统）

#### `load_characters` (GET /api/load_characters)
- ✅ 禁用文件系统时，仅从数据库加载
- ✅ 数据库未启用时返回错误

#### `get_conversation_detail` (GET /api/conversation/detail)
- ✅ 禁用文件系统时，仅从数据库加载
- ✅ 数据库失败时抛出错误（不再回退到文件系统）

#### `user/settings` (GET/POST /api/user/settings)
- ✅ 禁用文件系统时，仅使用数据库
- ✅ 数据库失败时抛出错误（不再回退到文件系统）

## 🔧 使用方法

### 启用仅数据库模式

在 `backend/config.py` 中设置：

```python
DISABLE_FILESYSTEM = True  # 仅使用数据库
```

### 恢复双写模式

在 `backend/config.py` 中设置：

```python
DISABLE_FILESYSTEM = False  # 数据库 + 文件系统（双写模式）
```

## ⚠️ 注意事项

1. **头像文件**：头像文件仍然保存到文件系统（`user_data/{username}/avatars/`），因为前端需要直接访问这些文件
2. **数据库必须启用**：禁用文件系统时，数据库必须正常工作，否则会返回错误
3. **数据安全**：建议定期备份数据库文件 `ponychat.db`
4. **测试建议**：在测试环境中先验证功能正常，再在生产环境使用

## 📊 性能优势

仅数据库模式的优势：
- ✅ **更快的查询速度**：索引查询比文件遍历快 10-200 倍
- ✅ **更好的数据一致性**：ACID 事务保证
- ✅ **更小的存储占用**：数据库压缩比 JSON 文件更高效
- ✅ **更容易备份**：单个数据库文件即可完整备份

## 🔍 验证方法

### 1. 检查日志

启动应用后，查看日志确认模式：

```
🗄️ [DB] 用户 xxx 数据已保存到数据库（仅数据库模式）
📁 [FS] 文件系统已禁用，跳过文件系统保存
```

### 2. 测试保存和加载

1. 保存数据：应该看到数据库保存日志，没有文件系统保存日志
2. 加载数据：应该看到数据库加载日志，没有文件系统加载日志
3. 检查文件系统：`user_data` 目录中的对话文件不应该更新（除了头像文件）

### 3. 数据库验证

```python
import sqlite3

conn = sqlite3.connect('ponychat.db')
cursor = conn.cursor()

# 检查数据
cursor.execute("SELECT COUNT(*) FROM conversations")
print(f"对话数: {cursor.fetchone()[0]}")

cursor.execute("SELECT COUNT(*) FROM messages")
print(f"消息数: {cursor.fetchone()[0]}")

conn.close()
```

## 🚨 故障排查

### 问题：数据库保存失败

**症状**：日志显示 `❌ [DB] 数据库保存失败`

**解决方案**：
1. 检查数据库文件权限
2. 检查磁盘空间
3. 查看详细错误日志
4. 考虑临时恢复双写模式：`DISABLE_FILESYSTEM = False`

### 问题：数据丢失

**症状**：某些数据无法加载

**解决方案**：
1. 检查数据库文件是否存在：`ponychat.db`
2. 运行迁移脚本重新同步：`python -m backend.db.migrate`
3. 如果数据库损坏，从备份恢复
