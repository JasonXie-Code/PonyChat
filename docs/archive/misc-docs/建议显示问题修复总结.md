# 建议显示问题修复总结（历史）

> **2026-04-24 说明**：产品已废除对话模式下的「建议问题」功能；对应后端 `POST /api/suggest-questions` 与客户端展示已移除。本文档仅作历史排障记录保留。

## 问题描述
后端成功生成了建议，但前端没有正确显示出来。

## 问题分析

### 日志分析
1. **后端日志**：
   - `13:57:34,004` - 第一个请求获取锁成功
   - `13:57:34,651` - 第二个请求被拦截（重复请求），返回 `skipped: True`
   - `13:57:36,442` - 第一个请求成功生成建议: `['好啊，来方糖屋玩刺激的！', '我想亲亲你的粉色身体']`

2. **前端日志**：
   - `13:57:33.601` - 建议数据已存入消息对象
   - 但前端没有显示建议

### 根本原因
1. **重复请求处理问题**：当后端返回 `skipped: True` 时，前端仍然处理了 `FALLBACK_QUESTIONS`，可能覆盖了已生成的建议数据。
2. **DOM更新时机问题**：当建议数据异步添加到消息对象后，DOM可能没有及时更新显示。

## 修复方案

### 1. 修复重复请求处理 (`js/chat/suggestions.js`)
**问题**：当后端返回 `skipped: True` 时，前端仍然处理 `FALLBACK_QUESTIONS`，可能覆盖已生成的建议。

**修复**：添加 `skipped` 检查，跳过重复请求的响应：
```javascript
// 🔧 [修复] 如果后端返回 skipped: True，说明已有其他请求在处理，不覆盖现有建议
if (data.skipped === true) {
    console.log(`${getTS()} ⏭️ [建议生成] 后端跳过重复请求，等待其他请求完成或通过同步获取建议`);
    // 不覆盖现有建议，等待同步或重试
    return;
}
```

### 2. 增强建议显示逻辑 (`js/chat/message-ui.js`)
**问题**：当消息对象中已有建议数据时，DOM可能没有及时更新显示。

**修复**：
- 使用双重 `requestAnimationFrame` 确保DOM已更新后再显示建议
- 添加详细的调试日志，便于排查问题
- 确保容器和内容元素存在后再渲染

```javascript
// 使用双重 requestAnimationFrame 确保DOM已更新
requestAnimationFrame(() => {
    requestAnimationFrame(() => {
        const container = document.getElementById(`suggest-container-${lastMsgIndex}`);
        const contentEl = document.getElementById(`suggest-questions-${lastMsgIndex}`);
        if (container && contentEl) {
            // ... 渲染逻辑
            if (window.renderExistingSuggestions) {
                console.log(`[建议显示] 渲染既存建议 (${lastItem.msg.suggestions.length}条)`);
                window.renderExistingSuggestions(container, contentEl, lastItem.msg.suggestions, lastMsgIndex);
            }
        }
    });
});
```

### 3. 数据库建议覆盖 (`js/conversations.js` 和 `js/core/sync.js`)
**问题**：如果数据库中有生成的建议选项，同步时应该覆盖前端显示的默认选项。

**修复**：
- **消息合并时覆盖默认建议** (`js/conversations.js`)：在 `applyDataToMemory` 中，当合并服务器和本地消息时，如果服务器消息有非默认建议，覆盖本地消息的默认建议。
- **同步后触发渲染** (`js/core/sync.js`)：在 `_syncMessages` 中，同步完成后检查是否有建议数据，如果有则触发渲染以确保显示。

```javascript
// js/conversations.js - 消息合并时覆盖默认建议
const mergedServerMsgs = serverMsgs.map((serverMsg, idx) => {
    const localMsg = localMsgs[idx];
    // 如果服务器消息有建议且不是默认占位符，使用服务器的建议
    if (serverMsg.suggestions && Array.isArray(serverMsg.suggestions) && serverMsg.suggestions.length > 0) {
        const isFallback = serverMsg.suggestions.every(q => 
            q === "那接下来呢？" || q === "我们将要聊什么？" || 
            q === "下一步呢？" || q === "我们要聊聊吗？"
        );
        // 如果服务器有非默认建议，或者本地没有建议，使用服务器的建议
        if (!isFallback || !localMsg?.suggestions || localMsg.suggestions.length === 0) {
            return { ...serverMsg };
        }
    }
    // 如果本地消息有建议且服务器没有，保留本地建议
    if (localMsg && localMsg.suggestions && Array.isArray(localMsg.suggestions) && localMsg.suggestions.length > 0) {
        return { ...serverMsg, suggestions: localMsg.suggestions };
    }
    return serverMsg;
});

// js/core/sync.js - 同步后触发渲染
if (!isGalgameMode && window.renderChat) {
    setTimeout(() => {
        const activeCharId = window.activeCharId;
        if (activeCharId) {
            const conv = window.getActiveConversation ? window.getActiveConversation(activeCharId) : null;
            if (conv && conv.messages && conv.messages.length > 0) {
                const lastMsg = conv.messages[conv.messages.length - 1];
                // 如果最后一条AI消息有建议数据，确保显示
                if (lastMsg && lastMsg.role === 'assistant' && lastMsg.suggestions && Array.isArray(lastMsg.suggestions) && lastMsg.suggestions.length > 0) {
                    console.log(`[同步服务] 🔄 检测到数据库中的建议数据，触发渲染以确保显示`);
                    window.renderChat(activeCharId, { 
                        isGalgameMode: false, 
                        isBackgroundSync: true,
                        isInstantScroll: false 
                    });
                }
            }
        }
    }, 100);
}
```

## 修复效果

1. **避免覆盖建议**：当后端返回 `skipped: True` 时，前端不再处理 `FALLBACK_QUESTIONS`，避免覆盖已生成的建议。
2. **确保正确显示**：使用双重 `requestAnimationFrame` 确保DOM已更新后再显示建议，并添加调试日志便于排查问题。
3. **数据库建议覆盖**：如果数据库中有生成的建议选项，在同步时会覆盖前端显示的默认选项。
