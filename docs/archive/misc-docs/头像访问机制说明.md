# 头像访问机制说明

## 🔍 重要澄清

**前端不会从旧目录读取数据！** 前端代码中的路径只是 HTTP 请求路径，不是文件系统路径。

---

## 📡 访问流程

### 1. 前端发送 HTTP 请求

前端代码中使用的是 **HTTP URL 路径**，例如：

```javascript
// 前端代码（js/ui/char-selection.js）
let avatarPath = char.avatar.startsWith('/') ? char.avatar : `/${char.avatar}`;
// 例如：avatarPath = "/user_data/Jason/avatars/1766937984934.jpg"

// 在 HTML 中使用
<img src="${avatarPath}" />
```

**这只是一个 HTTP 请求 URL**，不是直接访问文件系统！

---

### 2. 后端路由拦截请求

后端有一个专门的路由处理这些请求：

```python
# backend/routes/system.py
@router.get("/user_data/{username}/avatars/{filename}")
@router.get("/character_data/avatars/{filename}")
async def get_optimized_avatar(filename: str, username: Optional[str] = None):
    # 从新位置读取文件
    if username:
        path = os.path.join(USER_AVATARS_ROOT, username, filename)
        # USER_AVATARS_ROOT = "database/avatars/user_data"
        # 实际路径：database/avatars/user_data/{username}/{filename}
    else:
        path = os.path.join(CHARACTER_AVATARS_ROOT, filename)
        # CHARACTER_AVATARS_ROOT = "database/avatars/character_data"
        # 实际路径：database/avatars/character_data/{filename}
    
    # 返回文件内容给前端
    return FileResponse(path)
```

---

### 3. 后端从新位置读取文件

后端路由会从 **新位置** 读取文件：

- **用户头像**: `database/avatars/user_data/{username}/{filename}`
- **角色头像**: `database/avatars/character_data/{filename}`

**不会从旧位置读取**，因为：
1. 旧位置的文件已经被移动了
2. 代码中已经更新为新位置

---

## 🔄 完整流程示例

### 示例：用户头像访问

1. **前端代码**：
   ```html
   <img src="/user_data/Jason/avatars/1766937984934.jpg" />
   ```

2. **浏览器发送 HTTP 请求**：
   ```
   GET /user_data/Jason/avatars/1766937984934.jpg
   ```

3. **后端路由拦截**（`backend/routes/system.py`）：
   ```python
   @router.get("/user_data/{username}/avatars/{filename}")
   # username = "Jason"
   # filename = "1766937984934.jpg"
   ```

4. **后端从新位置读取**：
   ```python
   path = os.path.join(USER_AVATARS_ROOT, "Jason", "1766937984934.jpg")
   # 实际路径：database/avatars/user_data/Jason/1766937984934.jpg
   ```

5. **后端返回文件内容**：
   ```python
   return FileResponse(path)  # 返回图片数据
   ```

6. **浏览器显示图片**

---

## ✅ 关键点总结

### 前端不会直接访问文件系统

- ❌ **不是**：前端直接读取 `user_data/Jason/avatars/xxx.jpg`
- ✅ **而是**：前端发送 HTTP 请求到 `/user_data/Jason/avatars/xxx.jpg`

### 后端路由负责文件读取

- ✅ 后端路由拦截所有 `/user_data/...` 和 `/character_data/...` 请求
- ✅ 后端从新位置 `database/avatars/...` 读取文件
- ✅ 返回给前端

### 旧目录已经清空

- ✅ 旧目录 `user_data/{username}/avatars/` 中的文件已经移动到新位置
- ✅ 即使前端想从旧位置读取，也读不到（文件已经不在那里了）

---

## 📁 目录结构对比

### 旧结构（已迁移）
```
user_data/
└── Jason/
    └── avatars/          ❌ 已清空，文件已移动
        └── (空)
```

### 新结构（实际存储）
```
database/
└── avatars/
    ├── user_data/
    │   └── Jason/
    │       └── 1766937984934.jpg  ✅ 实际文件位置
    └── character_data/
        └── 1766866932936.jpg      ✅ 实际文件位置
```

---

## 🎯 结论

**前端不会从旧目录读取数据！**

- 前端只是发送 HTTP 请求
- 后端路由处理请求，从新位置读取文件
- 旧目录的文件已经移动，即使想读也读不到
- 前端代码中的路径只是 URL，不是文件系统路径

**所有头像访问都通过后端路由，后端自动从新位置读取！**
