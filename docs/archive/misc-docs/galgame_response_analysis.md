# Galgame 角色回复「兜兜转转」问题 —— 系统性分析

> 分析日期：2026-03-13  
> 现象：心理描写到位，但角色回复常岔开到食物/书籍，未跟上剧情发展

## 二、根因分析（五层）

### 2.1 角色设定层

- **饮食偏好**：设定中明确「喜欢吃炸干草汉堡包和雏菊三明治」「饮食喜好：雏菊三明治、炸干草汉堡包」
- **默认回复风格**：「每次回复2-4句话，最多80字」「回答有逻辑性，简洁，符合事实」
- **影响**：模型将「提议食物」视为安全、符合人设的默认行为

### 2.2 系统提示层（galgame_prompts.py）

- **延续与去重块**：`build_galgame_step_system_prompt()` 会把 `previous_scene_response` 注入为：
  ```
  - 上一回复 scene.response 参考（仅作事实参考，表述请全部重写）：
  ---
  {上一轮 response 原文}
  ---
  ```
- **问题**：当上一轮本身就是「魔法书/三明治」时，模型把这段当作**参考**，易理解为「换措辞即可」，而非「换话题」
- **当前约束**：只有「表述请全部重写」，未约束「话题/内容方向须针对玩家本轮行为」

### 2.3 历史消息层（slim payload）

- **骨架格式**：`玩家: {user_text}\n时间: ... | 地点: ... | 关系: ... | 心情: ...\n角色回复: {resp_text}`
- **历史示范**：8 条 assistant 骨架中，`角色回复` 几乎全是食物/书籍提议
- **因果缺失**：骨架只呈现「玩家做了什么 + 角色说了什么」，未体现「玩家行为 → 正确回应」的因果；且历史示范本身多为错误对应（抱抱→提议魔法书）

### 2.4 Instruction 层（Step 4）

- **注入位置**：instruction 追加到**最后一条 user 消息**末尾
- **结构**：`（我在被子下面悄悄摸了摸你的腰） /no_think` + 长 instruction
- **已有约束**：已加「直接回应玩家本轮行为」「紧跟剧情」「禁止岔开话题」
- **可能问题**：instruction 较长，模型可能优先关注格式/禁止清单，弱化对「玩家行为」的注意力

### 2.5 分步生成顺序

- Steps 1–3 先生成 env / body_state / thoughts，Step 4 再生成 response
- Step 4 的 instruction 中会传入 `prev_env`、`prev_body_state`、`prev_thoughts`（本轮已生成）
- **心理描写已正确**：thoughts 有「期待接下来会发生什么」，说明模型理解情境
- **response 脱节**：Step 4 未充分利用「心理描写已表达期待」这一信号，仍惯性输出食物提议

---

## 三、已实施的优化（本轮）

1. **Step 4 写作规范**：新增「紧跟剧情」——禁止岔开、须与心理描写一致
2. **Step 4 禁止清单**：新增「禁止岔开到与玩家本轮行为无关的话题」
3. **上一轮/查重重试**：对 response 步骤追加「须针对玩家本轮行为做出反应，不得岔开到无关话题」

## 四、建议的进一步优化

### 4.1 ✅ 已实施：延续与去重块强化（galgame_prompts.py）

在 `no_repeat_block` 的「上一回复 scene.response 参考」后增加逻辑说明：

```
若上一回复与玩家本轮行为无关或岔开到其他话题，本轮须针对玩家新行为做出反应，不得重复无关提议。
```

### 4.2 ✅ 已实施：Instruction 末尾插入玩家本轮行为

在 Step 4 instruction 的**末尾**插入（大模型对尾部更敏感）：

```
【玩家本轮行为】：（玩家消息原文）
```

从 last user message 提取并 strip /no_think。

### 4.3 低优先级：历史骨架裁剪或 response 去噪

- 方案 A：slim 时只保留最近 N 轮（如 4 轮），减少错误示范的累积
- 方案 B：骨架中的 `角色回复` 对明显「食物/书籍提议」类做摘要或省略（实现复杂，收益待验证）
