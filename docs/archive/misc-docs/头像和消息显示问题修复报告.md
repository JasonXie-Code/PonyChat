# 头像和消息显示问题修复报告

## 修复时间
2026-01-29 16:15

## 问题1: 用户头像没有正确加载

### 问题原因
1. **数据库表缺少 `avatar` 字段**：`users` 表没有 `avatar` 字段来存储头像路径
2. **`get_all_users()` 方法未返回头像**：即使有头像数据，也没有在查询中包含
3. **`get_profile` API 使用旧方法**：使用 `load_users()` 从数据库加载，但返回的数据中没有头像字段

### 修复内容

#### 1. 数据库 Schema 更新
- 在 `backend/db/database.py` 的 `users` 表定义中添加了 `avatar TEXT` 字段

#### 2. 数据库迁移
- 运行 `scripts/add_avatar_column.py` 为现有数据库添加 `avatar` 列

#### 3. UsersDAO 更新
- **`get_user()` 方法**：更新查询以包含 `avatar` 字段，并添加兼容性处理（如果字段不存在）
- **`get_all_users()` 方法**：更新查询以包含 `avatar` 字段，并添加兼容性处理
- **`update_user()` 方法**：添加 `avatar` 到 `allowed_fields` 列表，支持更新头像

#### 4. API 路由更新
- **`get_profile` API**：改为优先从数据库获取用户信息，如果数据库中没有头像，尝试从文件系统加载并更新数据库
- **`update_profile` API**：改为直接更新数据库，而不是使用 `save_users()`

#### 5. 数据迁移
- 运行 `scripts/migrate_user_avatars.py` 从备份文件迁移头像数据到数据库
- 成功迁移了 3 个用户的头像（Jason, 老吴, 小蝶）

## 问题2: 对话中显示了应该隐藏的 "..." 消息

### 问题原因
1. **后端创建占位符消息**：当 `last_user_content` 为空时，后端会创建内容为 "..." 的占位符消息
2. **`isHidden` 标记不正确**：占位符消息的 `isHidden` 标记依赖于 `request.isHidden`，而不是自动设置为 `True`
3. **前端过滤不完整**：前端只检查 `isHidden` 标记，但没有过滤内容为 "..." 的消息

### 修复内容

#### 1. 后端修复 (`backend/routes/chat.py`)
- 在 Galgame 模式的消息创建逻辑中，当 `last_user_content` 为空时，自动设置 `isHidden: True`
- 修改逻辑：`is_hidden = getattr(request, 'isHidden', False) or (not last_user_content and not last_user_image)`

#### 2. 前端修复 (`js/chat/message-ui.js`)
- 在 `renderMessageHTML` 函数中添加了过滤逻辑
- 如果消息内容为 "..."，直接返回空字符串，不渲染该消息

## 修复后的行为

### 头像加载
1. **数据库优先**：`get_profile` API 优先从数据库获取头像
2. **自动迁移**：如果数据库中没有头像但文件系统中有，自动迁移到数据库
3. **路由正确**：头像路由 `/user_data/{username}/avatars/{filename}` 正确映射到 `database/avatars/user_data/{username}/{filename}`

### 消息过滤
1. **后端自动隐藏**：空内容的占位符消息自动设置 `isHidden: True`
2. **前端双重过滤**：
   - 检查 `isHidden` 标记
   - 检查内容是否为 "..." 占位符
3. **确保不显示**：占位符消息不会在对话界面中显示
