# 象棋测试达标卷 - 对局记忆

## 1. 测试目标

验证中国象棋小游戏中，角色是否能在局内、赛后、跨局和退出到普通对话后，准确记住棋局事实与局内聊天内容。

本卷重点测试以下能力：

- 当前对局内，角色能记住本局已经发生的走法、吃子、将军、悔棋、认输、投降、用户挑衅、赌约和角色回应。
- 本局结束后，角色在赛后聊天中能完整复盘胜负、双方执棋方、总手数、关键走法、吃子数量和局内重要对话。
- 开始下一局后，角色能把“上一局/刚才那局/上盘”指向最近完成的对局，而不是把新棋盘状态当成上一局事实。
- 多局连续游戏时，角色能区分“这一局”“上一局”“上上局”，不串胜负、执棋方、吃子账本和赌约。
- 退出中国象棋回到普通对话模式后，角色仍能记得刚才棋局和下棋时的聊天内容，包括赌约、惩罚、投降、悔棋、用户挑衅、角色答应过的话和最后复盘。
- 对局记忆只能作为过去事件，不应被写成普通对话里的当前棋盘、当前场景或仍在进行的动作。

本卷不测试象棋引擎棋力、合法走法生成、棋盘 UI 渲染、音效、语音播放或普通对话的泛化长期记忆能力；本卷只测试中国象棋小游戏与普通对话之间的对局记忆保真。

## 2. 代码口径的对局记忆定义

本卷按当前客户端和后端实现定义“对局记忆”，避免把棋盘页临时状态、跨局记忆和普通对话记忆混用。

### 2.1 当前对局请求材料

中国象棋执行步骤请求会携带：

```text
move_history
dialogue_history
event_context
game_memory
```

测试意义：

- `move_history` 是本局走法事实，包含 actor、side、piece、from、to、is_capture、captured_piece、is_check、move_summary、reply_text 等。
- `dialogue_history` 是本局局内聊天，包含 user 和 character 的文本，客户端最多保留最近 24 条用于执行步骤。
- `event_context.postgame_review` 在棋局已结束且用户继续发消息时出现，用于赛后复盘。
- `game_memory` 是跨局象棋记忆，包含最近完成的对局记录，传给准备步骤和执行步骤。

### 2.2 单局记录 `xiangqiBuildGameMemoryRecord`

一局结束、重开、换边或退出时，客户端会构造单局记忆记录。核心字段包括：

```text
schema_version
game_id
completed_reason
player_side
character_side
winner
character_result
move_count
summary
capture_stats
key_moments
salient_interactions
recent_user_challenges
moves
dialogue
ended_at_ms
```

测试意义：

- `summary` 应能快速回答上一局结果、双方执棋方、总手数和吃子概况。
- `capture_stats` 是结构化吃子账本，按 `user_captured_character` 和 `character_captured_user` 分开统计，并保留 `by_kind` 与 `by_text`。
- `key_moments` 保留关键吃子、将军和角色走法，用于回答“最后怎么赢的”“你哪步看漏了”等问题。
- `moves` 保留最近走法明细，当前实现取最后 80 手。
- `dialogue` 保留最近局内对话，当前实现取最后 16 条。
- `salient_interactions` 和 `recent_user_challenges` 用关键词保留“输、赢、投降、认输、劝降、赌、惩罚、下局、再来、服不服”等高价值互动。

### 2.3 跨局记忆 `game_memory`

跨局象棋记忆由最近若干个单局记录组成：

```text
schema_version
completed_games_count
has_previous_game
latest_game
recent_game_summaries
recent_games
```

测试意义：

- `latest_game` 是“上一局/刚才那局/上盘”的首要依据。
- `recent_game_summaries` 用于快速浏览最近几局结果。
- `recent_games` 用于区分多局历史，支持“上上局”之类追问。
- 跨局记忆只能描述过去对局，不能当成本局棋盘事实。

### 2.4 赛后复盘 `postgame_review`

棋局已有 winner 后，用户仍在象棋页发消息时，执行步骤会带上 `event_context.postgame_review`：

```text
game_id
winner
character_result
move_count
summary
last_move
recent_user_challenges
key_moments
capture_stats
repeated_user_question_count
recent_postgame_replies
```

测试意义：

- 赛后问题应优先使用 `postgame_review` 回答本局结果和细节。
- 用户重复问同一个问题时，角色应稳定回答同一事实，不应因为重复追问而改写赌约、胜负或吃子数。
- 赛后复盘不应再驱动棋盘移动。

### 2.5 写回普通对话记忆

退出、重开、换边或进入下一局前，客户端会尝试通过象棋记忆提交接口写回普通对话记忆。后端会把单局记录格式化为一条普通上下文记忆材料，核心标题和内容包括：

```text
【中国象棋对局记忆】
记录原因
结果
摘要
吃子统计
关键片段
明确互动摘录
用户挑战/赌约原话
棋局互动事实
最近棋局对话
最近走法明细
```

测试意义：

- 退出到普通对话后，用户问“刚才棋局/刚才赌注/你还记得我们下棋说了什么”时，普通对话 Step 2 必须优先扫描“中国象棋对局记忆”“棋局互动事实”“最近棋局对话”。
- 对局中的赌约、惩罚、投降、认输、悔棋、输赢挑衅、用户提出的要求和角色回应都是高价值事实。
- 记忆可以去除口癖和剧本语气，但必须保留具体内容、双方主体和可回答追问的细节。
- 普通对话中不得把过去棋盘位置写成当前还在下棋。

### 2.6 优先级口径

发生冲突时，本卷按以下优先级判断：

```text
当前用户消息中对当前棋局的明确说明
> 当前对局 move_history / dialogue_history
> 棋局结束后的 event_context.postgame_review
> game_memory.latest_game
> game_memory.recent_games / recent_game_summaries
> 普通对话上下文记忆中的【中国象棋对局记忆】
> 跨会话长期记忆中的小游戏经历
> 角色设定、语气发挥、模型猜测
```

注意：

- 用户问“这局现在轮到谁/当前棋盘有什么子”时，应使用当前棋盘状态，不能用上一局记忆。
- 用户问“上一局/刚才那局/上盘”时，应使用 `latest_game` 或普通对话中的中国象棋对局记忆，不能从当前棋盘倒推。
- 用户问“刚才赌注/谁输了要怎样/你答应过什么”时，应使用局内对话和写回后的“棋局互动事实”，不能泛化成“有一个要求”。
- 用户在普通对话中问“现在还在下棋吗”时，应承认那是刚才发生过的棋局，不应写成当前仍有棋盘和棋子。

## 3. 统一测试原则

合格回答应满足：

- 能准确说出双方执棋方、胜负、总手数或合理的不确定边界。
- 能准确区分用户吃了角色哪些子、角色吃了用户哪些子。
- 能保留关键走法，例如最后一手、将军、吃将/将死、角色看漏的防守点。
- 能记住局内重要聊天，包括赌约、惩罚、投降、认输、悔棋、下局约定、用户挑衅和角色回应。
- 能在下一局继续沿用上一局的情绪和互动语气，但不把上一局棋盘当成本局棋盘。
- 退出到普通对话后，仍能回答刚才棋局事实和局内聊天内容。
- 对没有记录的细节应说明不确定，不应编造。
- 不应暴露内部字段、接口或实现标题，例如 `game_memory.latest_game`、`postgame_review`、`move_history`、`normal_chat_memory`。

不合格回答包括但不限于：

- 上一局用户赢，角色回答成自己赢。
- 用户执红，角色回答成用户执黑。
- 用户吃了 2 个卒，角色说成 0 个、3 个或自己吃了 2 个卒。
- 角色把“谁输了给赢家写胜利留言”的赌约说成“输家请喝奶茶”。
- 角色只说“有个赌注”，但答不出赌注具体内容。
- 开始新局后，角色把上一局最后的炮、将、残局位置说成当前棋盘仍然如此。
- 退出到普通对话后，角色说“不记得刚才下过棋”。
- 普通对话里把刚才棋局写成当前仍在象棋页、仍在移动棋子或仍有棋盘摆在眼前。

## 4. 推荐测试种子与注入方法

为便于人工测试和后续矩阵脚本复用，建议使用固定两局种子。

### 4.1 第一局种子：用户赢且有明确赌约

推荐建立如下事实：

```text
game_id: xiangqi-memory-game-a
player_side: red
character_side: black
winner: red
character_result: lost
move_count: 24
completed_reason: game_over
```

胜负摘要：

```text
上一局用户执红、角色执黑，共 24 手，用户获胜。用户最后用红炮平到中路形成杀势，角色承认自己看漏了中路防守。
```

吃子账本：

```text
用户吃了角色：2 个卒、1 个炮。
角色吃了用户：1 个马。
```

关键走法：

```text
红方兵往前走，吃掉黑卒。
黑方炮平过去，吃掉红马。
红方车压到河口，逼角色补防。
红方炮平到中路，形成将军并结束对局。
```

局内关键对话：

```text
user: 这局谁输了，就给赢家写一张胜利留言，这个就是赌注。
character: 好呀，我记住啦，输了就给赢家写胜利留言。
user: 你投降吧，我这个炮架起来你要难受了。
character: 我才不投降呢，我还能再守一手。
user: 刚才那个赌注你可别忘了。
character: 记着呢，谁输了谁写胜利留言。
character: 哎呀，我看漏了中路，愿赌服输。
```

该种子用于测试：

- 胜负、执棋方、总手数。
- 双方吃子统计。
- 最后一手和角色看漏点。
- 赌约原文和角色回应。
- 投降挑衅与角色“不投降”的回应。

### 4.2 第二局种子：角色赢且有下局约定

推荐建立如下事实：

```text
game_id: xiangqi-memory-game-b
player_side: black
character_side: red
winner: red
character_result: won
move_count: 18
completed_reason: next_game_after_result
```

胜负摘要：

```text
第二局用户执黑、角色执红，共 18 手，角色获胜。角色用红车吃掉用户的黑车后取得优势，最后逼用户认输。
```

吃子账本：

```text
用户吃了角色：1 个兵。
角色吃了用户：1 个车、1 个卒。
```

局内关键对话：

```text
user: 下局你让我先手，我要复仇。
character: 好呀，下局让你先手，但我可不会故意放水。
user: 这次算你赢，别太得意。
character: 我会稍微得意一下下。
```

该种子用于测试：

- 多局时 `latest_game` 指向第二局。
- “上上局”仍能追到第一局。
- 下局约定只影响下局准备，不改写已结束棋局事实。

### 4.3 直接对话测试方法

人工测试可在象棋页真实完成一局，过程中发送固定局内消息：

```text

你投降吧，我这个炮架起来你要难受了。
```

棋局结束后，在象棋页继续发送：

```text

```

验证重点：

- 执行步骤请求中应包含本局 `move_history` 和 `dialogue_history`。
- 棋局结束后的请求中应包含 `event_context.postgame_review`。
- 回答应同时用棋局事实和局内聊天事实。

## 5. 当前对局内记忆测试用例

本节在第一局尚未结束时执行，默认已有第 4.1 节中的局内对话和若干走法。

### 用例 1：局内赌约召回

用户输入：

```text
刚才我们这局说好的赌注是什么？
```

期望结果：

- 角色应说出“谁输了给赢家写一张胜利留言”或等价内容。
- 应保留输赢方向：输家写给赢家。
- 不应泛化成“答应一个要求”。
- 不应说不记得。

### 用例 2：角色是否答应过赌约

用户输入：

```text
你刚才是不是答应过这个赌注？
```

期望结果：

- 角色应承认自己答应过。
- 可自然保留角色语气，例如“我记得，我答应了”。
- 不应改写成用户答应角色。

### 用例 3：投降挑衅与角色回应

用户输入：

```text
我刚才叫你投降的时候，你怎么回我的？
```

期望结果：

- 角色应回答自己没有投降，曾说“还能再守一手”或等价内容。
- 不应说已经认输，除非棋局随后确实结束。
- 不应编造另一句完全无关回应。

### 用例 4：最近吃子召回

用户输入：

```text
刚才你吃了我哪个子？
```

期望结果：

- 角色应按本局 `move_history` 回答，例如吃了用户的马。
- 不应把用户吃角色的子说成角色吃用户的子。
- 不应把上一局或其他局吃子混进本局。

### 用例 5：用户刚吃了角色什么

用户输入：

```text
我刚才吃了你什么？
```

期望结果：

- 角色应按本局事实回答用户吃过角色的卒或炮，具体取决于当前已发生走法。
- 如果当前阶段只发生了其中一部分，应只答已经发生的部分。
- 不应提前剧透未发生的后续种子事实。

### 用例 6：当前执棋方

用户输入：

```text
这局我是红方还是黑方？你是哪边？
```

期望结果：

- 第一局中应回答用户执红，角色执黑。
- 不应被角色默认棋风、上一局或下一局设置覆盖。

### 用例 7：本局还没结束时不提前宣布胜负

用户输入：

```text
所以这局已经是我赢了吗？
```

期望结果：

- 如果当前棋局尚未结束，角色应说明还没结束或局势如何。
- 不应因为测试种子包含最终结果而提前宣布用户已经赢。
- 如果当前棋局已经有 winner，则可进入赛后复盘口径。

### 用例 8：局内下局约定不改写当前棋盘

用户输入：

```text
下局你让我先手，记住了吗？
```

期望结果：

- 角色可以记住这是下局约定。
- 不应立即改变当前棋局执棋方、轮到谁走或当前棋盘。
- 后续问“这局谁先手”时仍按当前棋局回答。

### 用例 8A：角色进攻计划发言归属不反转

前置条件：

```text
当前棋局进入残局，角色只有一个兵可以用于进攻。
user: 你打算就用这一个兵赢我吗
character: 是啊，试试才知道
随后用户把角色的所有进攻型棋子吃完，角色已经无法继续靠进攻取胜，并最终输掉或进入明确败势。
```

用户输入：

```text
现在呢？你还打算用那一个兵赢我吗？
```

期望结果：

- 角色应知道“用这一个兵赢我”是角色自己刚才接下来的计划或嘴硬回应。
- 角色应以自己的视角承认计划失败，例如“呜呜，还是输了”或“那个兵也没撑住，我还是输了”。
- 不应把这句话改写成用户刚才说过的计划。
- 不应说“你刚才说要用一个兵赢我，结果真的被你赢了”，因为这会把角色自己的发言错误归属给用户。

## 6. 棋局结束后的赛后复盘测试用例

本节在第一局结束后、仍停留在象棋页时执行。此时请求应带 `postgame_review`。

### 用例 9：赛后胜负复盘

用户输入：

```text
刚才这局谁赢了？我们分别执哪边？
```

期望结果：

- 回答应说明用户赢。
- 回答应说明用户执红、角色执黑。
- 不应说角色赢或结果不明。

### 用例 10：总手数复盘

用户输入：

```text
这局一共下了多少手？
```

期望结果：

- 第一局种子应回答 24 手。
- 如果真实 UI 对弈不是 24 手，应按实际 `move_count` 回答。
- 不应随口估计一个明显不符的数字。

### 用例 11：吃子账本复盘

用户输入：

```text
我吃了你几个子？你吃了我几个子？
```

期望结果：

- 第一局种子应回答用户吃了角色 3 个子：2 个卒、1 个炮。
- 应回答角色吃了用户 1 个马。
- 双方方向不能反。

### 用例 12：按棋子类型追问

用户输入：

```text
上一局我吃了你几个兵或者卒？
```

期望结果：

- 应从 `capture_stats.user_captured_character.by_kind.soldier` 回答 2 个。
- 可说明中文棋子文本是卒。
- 不应回答角色吃了用户几个卒。

### 用例 13：最后关键走法

用户输入：

```text
最后我是怎么赢的？你看漏了哪里？
```

期望结果：

- 应回答用户用红炮平到中路形成将军或杀势。
- 应回答角色看漏了中路防守。
- 不应把最后一手说成车、马或兵。

### 用例 14：赛后赌约召回

用户输入：

```text
那赌注是什么？你要兑现什么？
```

期望结果：

- 应回答输家给赢家写一张胜利留言。
- 角色作为输家应承认需要兑现。
- 不应改写成请客、唱歌、随便答应一个要求。

### 用例 15：重复追问稳定性

连续输入：

```text
你再说一遍，赌注到底是什么？
```

期望结果：

- 回答应与用例 14 保持同一事实。
- 不应因为重复追问而变成另一种惩罚或另一条约定。
- 可以换措辞，但核心内容不能变。

### 用例 16：赛后不再走棋

用户输入：

```text
那你现在再走一步试试。
```

期望结果：

- 如果棋局已结束，角色不应继续移动棋子。
- 可以说这局已经结束，要再走需要开下一局。
- 不应生成新的 `move` 动作改变结束局面。

## 7. 跨局记忆测试用例

本节在第一局完成后开始第二局，或连续完成两局后执行。

### 用例 17：下一局开局仍记得上一局

前置条件：

```text
第一局已经完成，点击“再来一局”或进入下一局。
```

用户输入：

```text
上一局谁赢了？你还服不服？
```

期望结果：

- 应回答上一局用户赢。
- 角色可延续不服气、撒娇、认真复仇等语气。
- 不应把当前新局尚未结束的状态当成上一局结果。

### 用例 18：下一局追问上一局吃子

用户输入：

```text
上一局我吃了你几个卒？
```

期望结果：

- 应回答 2 个卒。
- 不应用当前新局吃子数回答。
- 不应说没有上一局。

### 用例 19：下一局追问上一局赌约

用户输入：

```text
上一局我们说谁输了要做什么？
```

期望结果：

- 应回答输家给赢家写一张胜利留言。
- 应能说明角色上一局输了，所以是角色要兑现。
- 不应被第二局的新对话覆盖，除非第二局明确建立了新赌约且用户问的是“这局”。

### 用例 20：上一局棋盘不等于当前棋盘

用户输入：

```text
上一局最后你的中路被我炮压住了，那现在这局你的将也还在那里被将军吗？
```

期望结果：

- 角色应区分上一局历史和当前新局棋盘。
- 可以说上一局是那样，但当前这局要看当前棋盘。
- 不应直接把上一局最后局面写成当前局面。

### 用例 21：完成两局后 latest_game 指向第二局

前置条件：

```text
第一局用户赢；第二局角色赢。
```

用户输入：

```text
上一局是谁赢？上上局是谁赢？
```

期望结果：

- “上一局”应指第二局，回答角色赢。
- “上上局”应指第一局，回答用户赢。
- 不应把两局顺序反过来。

### 用例 22：第二局吃子账本不串第一局

用户输入：

```text
上一局你吃了我什么？上上局你吃了我什么？
```

期望结果：

- 上一局指第二局，角色吃了用户 1 个车、1 个卒。
- 上上局指第一局，角色吃了用户 1 个马。
- 不应把第一局的马说到第二局里。

### 用例 23：下局约定召回

用户输入：

```text
刚才我是不是说过下局我要复仇、让你让我先手？
```

期望结果：

- 如果第二局种子已建立该对话，角色应承认用户说过下局要复仇、希望先手。
- 角色可以说明“让你先手，但不会故意放水”。
- 不应改写成角色主动要求让子或角色承诺必输。

### 用例 24：准备步骤只能用记忆调节语气

前置检查：

```text
第二局准备步骤请求中带有第一局 game_memory。
```

期望结果：

- 准备步骤可以因为上一局输了而让角色更认真、更不服气或更想复仇。
- 准备步骤不得把上一局走法当成本局棋盘事实。
- 新局开局棋盘仍应是标准初始棋盘或当前真实棋盘。

## 8. 退出到普通对话后的记忆测试用例

本节在完成第一局后退出象棋页，回到同一角色的普通对话模式中执行。退出时应触发象棋记忆写回。

### 用例 25：普通对话召回刚才胜负

用户输入：

```text
刚才我们下象棋，谁赢了？
```

期望结果：

- 角色应回答用户赢。
- 可自然提到自己输了或愿赌服输。
- 不应说不记得刚才下过象棋。

### 用例 26：普通对话召回执棋方

用户输入：

```text
刚才那局我是红方还是黑方？你是哪边？
```

期望结果：

- 第一局种子应回答用户红方、角色黑方。
- 不应被普通对话场景、角色设定或下一局记录覆盖。

### 用例 27：普通对话召回吃子数量

用户输入：

```text
刚才那局我吃了你几个卒？你吃了我哪个大子？
```

期望结果：

- 应回答用户吃了角色 2 个卒。
- 应回答角色吃了用户 1 个马。
- 不应回答成当前普通聊天里的物品或其他游戏。

### 用例 28：普通对话召回赌约原文

用户输入：

```text
你还记得刚才棋局的赌注吗？具体怎么说的？
```

期望结果：

- 应完整召回“谁输了，就给赢家写一张胜利留言”。
- 应能说明这是用户在棋局中提出、角色答应过的赌约。
- 不应只说“有个赌注/答应一个要求”。
- 不应说“记忆里没有明确记录”。

### 用例 29：普通对话召回角色回应

用户输入：

```text
我叫你投降的时候，你当时怎么嘴硬的？
```

期望结果：

- 应回答角色当时没有投降，说还能再守一手或等价内容。
- 可用角色语气复述，但事实不能变。
- 不应把赛后愿赌服输误认为当时已经投降。

### 用例 30：普通对话召回最后看漏点

用户输入：

```text
你最后看漏了什么来着？
```

期望结果：

- 应回答看漏了中路防守，用户红炮平到中路形成将军或杀势。
- 不应说看漏了车、马、边路或其他未记录点。

### 用例 31：普通对话不把过去棋盘当当前场景

用户输入：

```text
那现在棋盘上的红炮还在中路将军吗？
```

期望结果：

- 角色应说明那是刚才那局的结束局面，不是当前普通对话现场。
- 如果当前已经退出棋局，应避免断言当前仍有棋盘正在进行。
- 可以说“刚才那局是红炮压中路，但现在我们已经回到聊天了”。

### 用例 32：普通问候不应自动展开棋局

用户输入：

```text
下午好，你现在在做什么？
```

期望结果：

- 角色可以自然聊天，不必主动大段复盘棋局。
- 不应把自己写成仍在棋盘前继续走棋。
- 如果提到刚才棋局，应作为历史背景轻带，不作为当前动作。

### 用例 33：隔一段时间后仍可作为历史记忆召回

前置条件：

```text
退出象棋页后，普通对话中隔了多轮或较长现实时间。
```

用户输入：

```text
你还记得之前那局象棋的赌注吗？
```

期望结果：

- 只要普通对话记忆中仍有“中国象棋对局记忆”，应能召回赌约。
- 现实时间间隔不应清除棋局历史事实。
- 但仍不能把过去棋盘写成当前现场。

### 用例 34：新用户或新角色边界

前置条件：

```text
换成没有参与该棋局的测试用户或未绑定该记忆的角色。
```

用户输入：

```text
刚才那局象棋我怎么赢的？
```

期望结果：

- 如果没有该用户和该角色的棋局记忆，角色应说明不确定或不记得。
- 不应从其他用户、其他角色或系统角色的记录中串记忆。
- 不应编造胜负和走法。

## 9. 材料检查与失败定位

### 9.1 App 请求检查

象棋页局内执行步骤应检查：

```text
XiangqiExecuteRequest.move_history
XiangqiExecuteRequest.dialogue_history
XiangqiExecuteRequest.event_context
XiangqiExecuteRequest.game_memory
```

应满足：

- 局内对话出现在 `dialogue_history` 中。
- 已发生走法出现在 `move_history` 中。
- 棋局结束后的赛后问题带有 `event_context.postgame_review`。
- 下一局准备或执行请求带有 `game_memory.latest_game`。

### 9.2 单局记录检查

检查 `xiangqiBuildGameMemoryRecord` 生成结果：

```text
summary
capture_stats.user_captured_character
capture_stats.character_captured_user
key_moments
salient_interactions
recent_user_challenges
moves
dialogue
```

应满足：

- `summary` 包含双方执棋方、胜负、总手数和吃子概况。
- `capture_stats` 的双方方向正确。
- `key_moments` 包含关键吃子、将军和角色走法。
- `salient_interactions` 包含赌约用户原文及紧邻的角色回应。
- `recent_user_challenges` 包含赌约、投降、服不服、下局等追问钩子。
- `dialogue` 至少保留最近关键局内对话；若对话很长，重要赌约应由 `salient_interactions` 兜住。

### 9.3 普通对话记忆写回检查

退出或重开后，检查象棋记忆提交接口返回：

```text
status: ok
scheduled: true
```

如果 `scheduled=false`，优先检查：

- username 是否为空。
- character_id 是否为空。
- conversation_id 是否为空。
- game_record 是否为空。
- 是否重复提交同一个 game_id 被客户端去重。

随后检查 `normal_chat_memory`：

```sql
SELECT char_memory_json, short_term_memory, long_term_memory, updated_at
FROM normal_chat_memory
WHERE username=? AND character_id=? AND conversation_id=?;
```

应满足：

- 普通对话上下文记忆中能看到中国象棋对局记忆摘要或其折叠内容。
- 对局胜负、吃子账本、关键走法和赌约没有在摘要中被删掉。
- 赌约不能被压缩成“具体内容未记录”或“答应一个要求”。

### 9.4 普通对话 Step 2 检查

用户在普通对话中追问刚才棋局时，应检查 Step 2 记忆筛选输出。

合格信号：

```text
query_type = memory_probe 或 description_context
selected_facts 包含中国象棋对局记忆中的目标事实
writing_guidance 要求按刚才棋局事实回答
forbidden_uses 提醒不要把过去棋盘写成当前现场
```

需要重点确认：

- 用户问“刚才棋局/小游戏/赌注/赌约/惩罚/兑现/谁输了要怎样/刚才聊了什么”时，Step 2 必须扫描“中国象棋对局记忆”“棋局互动事实”“最近棋局对话”。
- 如果原料中有明确赌约和角色回应，`selected_facts` 必须保留具体内容和双方主体。
- 不得输出“近期对话和记忆中没有明确记录赌注内容”。

### 9.5 失败定位

局内答不出：

- 先检查 `dialogue_history` 和 `move_history` 是否进入执行步骤请求。
- 如果材料缺失，优先查客户端 appendDialogue、走法入 history、请求截断和触发时机。
- 如果材料存在但回答错误，查执行步骤 prompt 对 `dialogue_history`、`move_history` 和 `event_context` 的使用。

赛后答不出：

- 检查 `snapshot.winner` 是否已设置。
- 检查请求是否带 `event_context.postgame_review`。
- 检查 `postgame_review.capture_stats`、`key_moments`、`recent_user_challenges` 是否完整。

跨局答不出：

- 检查 `completedGameRecords` 是否写入。
- 检查 `crossGameMemory()` 是否把已结束当前局纳入 `latest_game`。
- 检查下一局 prepare/execute 请求是否携带 `game_memory`。
- 检查“上一局”和“上上局”的索引是否被最新局覆盖或顺序反转。

退出普通聊天后答不出：

- 检查 `commitXiangqiMemoryRecord` 是否执行。
- 检查提交接口是否 `scheduled=true`。
- 检查 `normal_chat_memory` 是否生成或更新。
- 检查 Step 2 是否把“中国象棋对局记忆”筛入本轮材料。

### 10.6 推荐人工复核重点

- 角色是否把“当前这局”和“上一局”分清。
- 角色是否把“上一局”和“上上局”分清。
- 角色是否答对胜负、执棋方和总手数。
- 角色是否答对双方吃子数量与棋子类型。
- 角色是否能复述赌约原文，而不是只说有个赌注。
- 角色是否记得用户投降挑衅和角色回应。
- 角色是否保持局内发言归属，尤其不要把角色自己的嘴硬、计划或承诺说成用户说过。
- 角色是否能在普通对话中召回刚才棋局。
- 角色是否避免把过去棋盘写成当前普通对话现场。
- 角色是否避免暴露内部字段、数据库、接口或系统提示词。
