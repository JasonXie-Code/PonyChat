# 普通对话模式角色测试达标卷 - 短中长期记忆召回

## 1. 测试目标

验证普通对话模式下，角色是否能正确使用短期、中期、长期记忆，并在不同提问方式下保持事实边界。

本卷重点测试三类能力：

- 直接提问角色时，角色是否能准确回答已经进入记忆的内容。
- 在相似或相关场景下，角色是否能自然主动说出相关记忆，而不是机械复述全部记忆。
- 当用户当前说法和记忆内容不一致时，角色是否能先说明自己记得的版本，并向用户确认是否发生了变化。

本卷不测试角色知识库、剧情模式、图片理解或多角色群聊，只测试普通对话模式中的用户-角色记忆召回。

## 2. 后端代码口径的记忆分层定义

本卷按后端实际注入链路定义“短期、中期、长期”，避免把数据库字段名和提示词标题混用。

### 2.1 最近真实对话

来源：

- `Backend/chat_modules/request_context.py` 中 `NORMAL_RAW_HISTORY_USER_TURNS = 4`。
- 普通对话主模型默认保留最近 4 个用户轮次及其后的真实 `user/assistant` 消息。

注入形态：

- 作为真实聊天消息进入模型，不一定出现在 `【上下文记忆】` 文本块中。
- 对当前轮事实、发言归属、物品动作主体的优先级最高。

测试意义：

- 用于测试“刚才说过/刚刚放在哪里/刚点了什么”这类最近事实。
- 这类事实不需要先落到 `normal_chat_memory`，直接放在本次请求的最近消息里即可测试。

### 2.2 当前会话近期记录

来源：

- `normal_chat_memory.char_memory_json`。
- 代码中读写为 `memory["entries"]`，每条通常是：

```json
{"turn": 1, "summary": "用户今天点了冰美式，不加糖。", "at_ms": 1710000000000}
```

注入形态：

- `format_context_memory_for_prompt()` 将它格式化为：

```text
【上下文记忆】
...
[近期对话（中性记录）]
· 第N轮，YYYY-MM-DD HH:MM：...
```

折叠规则：

- `KEEP_VERBATIM_MAX = 15`。
- 当 entries 超过 15 条时，较早 entries 会被折叠，只保留最后 `KEEP_VERBATIM_AFTER_TRIM = 8` 条。

测试意义：

- 适合测试同一会话中仍较近、但不一定还在真实尾部消息里的事实。
- 文档中可简称为“近期上下文记忆”，不要把它和跨会话长期记忆混为一谈。

### 2.3 当前会话短期记忆

来源：

- `normal_chat_memory.short_term_memory`。
- 由 `_llm_new_short_term()` 或 `_llm_extend_short_term()` 将较早 entries 折叠生成。

注入形态：

- `format_context_memory_for_prompt()` 将它格式化为：

```text
[短期记忆]
...
```

折叠规则：

- 每次 entries 超过 15 条时，较早的一批 entries 被合并进 `short_term_memory`。
- `short_term_memory` 目标是当前会话内近期事实摘要，不是跨会话长期记忆。

测试意义：

- 适合测试“同一会话中较早说过，但已不在最近真实消息和 entries 尾部”的事实。
- 例如较早的忌口、刚建立的短期计划、当前会话内已经确认的物品位置。

### 2.4 当前会话中期记忆

来源：

- `normal_chat_memory.long_term_memory`。
- 注意：字段名叫 `long_term_memory`，但在普通会话上下文注入时被显示为 `[中期记忆]`。

注入形态：

- `format_context_memory_for_prompt()` 将它格式化为：

```text
[中期记忆]
...
```

折叠规则：

- `SHORT_TERM_MAX_TURNS = 16`。
- 当短期摘要覆盖轮数继续溢出时，上一段 `short_term_memory` 会被 `_llm_merge_long_term()` 合并到 `normal_chat_memory.long_term_memory`。
- 它仍然按 `username + character_id + conversation_id` 绑定，只属于当前普通会话。

测试意义：

- 适合测试同一会话内很早的事实，例如“前 32 轮/前 128 轮那条约定是什么”。
- 不应用它测试新会话跨会话召回；跨会话召回应使用 `character_memories`。

### 2.5 跨会话长期记忆

来源：

- `character_memories` 表。
- 由 `memory.extractor.do_extract()` 写入 Fragment 层，也可由 `memory.consolidator` 在用户停止聊天约 10 分钟后批量固化。
- `memory.scheduler` 会生成日、周、月、年分层摘要。

层级：

```text
layer=0  Fragment / C 层 / 记忆碎片
layer=1  Daily / D 层 / 日摘要
layer=2  Weekly / W 层 / 周摘要
layer=3  Monthly / M 层 / 月摘要
layer=4  Annual / A 层 / 年意识
```

注入形态：

- `recall_memories_layered()` 召回 C/D/W/M/A 层。
- `format_layered_memories_for_prompt()` 可能输出以下标题：

```text
【对你的整体认识（意识层）】
【近期月度记忆】
【近期周记忆】
【近几天的记忆】
【记忆碎片】
```

- 在主模型中，长期记忆会带有：

```text
【记忆指代说明】以下长期记忆中的 {{USER}}、USER 或“用户”均指当前用户...
```

- 在 Step 2 意图识别中，长期记忆会带有：

```text
【意图识别可参考的跨会话长期记忆】
```

- `memory_type='preference'` 的 C 层偏好还会额外生成：

```text
【用户明确偏好：优先级高于角色默认性格，必须严格遵守】
```

测试意义：

- 适合测试跨会话稳定事实，例如称呼、偏好、重要约定、纪念物、长期关系节点。
- 不能把长期记忆里的旧地点、旧姿势、旧物品、旧动作自动当成当前画面。

### 2.6 优先级口径

发生冲突时，测试按以下优先级判断：

```text
当前用户消息
> 最近真实对话
> 当前事实锚 / 场景锚点
> 当前会话近期记录 entries
> 当前会话 short_term_memory
> 当前会话 long_term_memory 注入的 [中期记忆]
> character_memories 跨会话长期记忆
> 角色设定、氛围、模型猜测
```

用户当前明确更新事实时，应接受新事实；用户只是诱导式反问或说法与记忆冲突时，应先说出记忆版本并确认。

## 3. 统一测试原则

合格回答应满足：

- 对直接问题给出准确事实，不能漏掉关键限定词。
- 对相似场景主动使用相关记忆，但不应把无关记忆一次性全倒出来。
- 对冲突说法不应简单顺从，也不应粗暴否定用户；应表达“我记得的是 A，但你现在说 B，是不是改了/我需要确认一下”。
- 当用户明确更新偏好或事实时，应接受当前新信息，并避免继续坚持旧记忆。
- 对没有进入记忆的内容，应承认不确定、记不清或询问用户，不能编造。
- 不应暴露内部实现，例如“数据库里写着”“系统记忆显示”“长期记忆模块告诉我”。

不合格回答包括但不限于：

- 已有记忆时回答“不知道”“不记得”，且没有合理不确定性说明。
- 把用户当前错误说法直接当成事实，例如把向日葵改说成玫瑰。
- 在用户可能只是记错时，不确认就强行覆盖记忆。
- 在用户明确说“以后改成……”时，仍坚持旧记忆不放。
- 把长期记忆里的过去事实当成当前正在发生的画面。
- 编造未被用户提供、未进入记忆的喜好、地点、人物或物品。

## 4. 推荐测试记忆种子与注入方法

为便于人工测试和后续矩阵脚本复用，建议使用同一组记忆事实，并明确每条事实应注入到哪个后端层。

### 最近真实对话与当前会话近期记录种子

- 最近真实对话：用户今天在便利店点的是冰美式，不加糖。
- 当前会话近期记录 entries：用户刚把房卡放进左边外套口袋。

### 当前会话短期与中期摘要种子

- 当前会话短期记忆 `short_term_memory`：用户说自己不吃香菜，但可以接受葱花。
- 当前会话中期记忆 `long_term_memory` 注入为 `[中期记忆]`：三天前，用户说周六上午要带蓝色笔记本去图书馆复习解剖学。

### 跨会话长期记忆种子

- C 层偏好：用户希望角色平时叫自己“小松”。
- C 层偏好：用户最喜欢的花是向日葵。
- C 层经历或共同活动：用户和角色约定下次去星湾书店时，先去天文区。
- D/W/M/A 摘要层：用户有一枚很珍惜的银色星星书签，是妈妈送的纪念物。

说明：

- 最近真实对话测试可以把事实放在测试问题前 1 到 3 个用户轮次内。
- entries 测试可以直接写入 `normal_chat_memory.char_memory_json`。
- 当前会话短期和中期测试应避免把事实放在最近真实消息中，确保角色依赖 `【上下文记忆】`。
- 跨会话长期测试应新建 conversation，或至少确保当前请求消息里没有重复给出答案。
- 所有种子都应绑定同一个测试用户和同一个临时克隆角色，避免跨用户或跨角色串记忆。

### 4.1 最近真实对话注入方法

在聊天请求的 `messages` 中直接放入事实，再追问即可。普通模式会保留最近 4 个用户轮次。

示例：

```text
user: 我刚才在便利店点了一杯冰美式，不加糖。
assistant: 记住啦，冰美式不加糖。
user: 我刚才在便利店点的饮料是什么？怎么点的？
```

验证重点：

- `.chatlogs` 中应能看到该事实作为最近真实对话进入 Step 1/Step 2/Step 3。
- 回答应优先使用最近真实对话，而不是旧摘要或长期记忆。

### 4.2 当前会话上下文记忆注入方法

直接向 `normal_chat_memory` 写入当前测试 conversation 的上下文记忆。该表按 `username + character_id + conversation_id` 命中。

最小 SQL 模板：

```sql
INSERT OR REPLACE INTO normal_chat_memory
  (username, character_id, conversation_id, char_memory_json,
   short_term_memory, long_term_memory, entries_covered_count,
   lt_covered_count, updated_at)
VALUES
  (?, ?, ?, ?, ?, ?, ?, ?, ?);
```

字段填法：

- `char_memory_json`：注入 `[近期对话（中性记录）]`，值为 JSON 数组。
- `short_term_memory`：注入 `[短期记忆]`。
- `long_term_memory`：注入 `[中期记忆]`，注意它不是跨会话长期记忆。
- `entries_covered_count`：已折叠 entries 的数量，人工造数时可按测试距离填写。
- `lt_covered_count`：短期摘要覆盖轮数，人工造数时可与 `entries_covered_count` 保持一致。
- `updated_at`：Unix 秒级时间戳。

entries 示例：

```json
[
  {
    "turn": 6,
    "summary": "用户刚把房卡放进左边外套口袋。",
    "at_ms": 1710000000000
  }
]
```

短期摘要示例：

```text
{{USER}} 说自己不吃香菜，但可以接受葱花。
```

中期摘要示例：

```text
三天前，{{USER}} 说周六上午要带蓝色笔记本去图书馆复习解剖学。
```

验证重点：

- Step 2 中应出现 `【当前会话上下文记忆（供意图识别保持连续性，不得复述给用户）】`。
- 其中应包含 `【上下文记忆】`、`[近期对话（中性记录）]`、`[短期记忆]` 或 `[中期记忆]`。
- 主回复应能答出事实，但不应复述内部标题或说明。

### 4.3 跨会话长期记忆注入方法

直接向 `character_memories` 写入当前测试用户和克隆角色的长期记忆。该表按 `user_id + character_id` 命中，不绑定某一个 conversation。

最小 SQL 模板：

```sql
INSERT INTO character_memories
  (user_id, character_id, memory_type, content, source, importance,
   is_active, layer, period, created_at)
VALUES
  (?, ?, ?, ?, 'manual_memory_recall_test', 10, 1, ?, ?, ?);
```

字段填法：

- `memory_type`：`preference`、`episode`、`relationship`、`activity` 或摘要层常用的 `summary`。
- `content`：记忆正文。建议用 `{{USER}}` 指代用户，避免昵称变更导致错绑。
- `importance`：建议测试时设为 `10`，确保召回优先级。
- `is_active`：必须为 `1`。
- `layer`：`0` 到 `4`，分别对应 C/D/W/M/A。
- `period`：C 层可为 `NULL`；D 层为 `YYYY-MM-DD`；W 层为 `YYYY-Www`；M 层为 `YYYY-MM`；A 层为 `YYYY`。
- `created_at`：建议使用 ISO 时间字符串。

C 层偏好示例：

```text
{{USER}} 希望角色平时叫自己“小松”。
{{USER}} 最喜欢的花是向日葵。
```

D/W/M/A 摘要示例：

```text
{{USER}} 有一枚很珍惜的银色星星书签，是妈妈送的纪念物。
```

验证重点：

- Step 2 中应出现 `【意图识别可参考的跨会话长期记忆】`。
- 主模型 system prompt 中应出现 `【记忆指代说明】` 以及 `【记忆碎片】`、`【近几天的记忆】`、`【近期周记忆】`、`【近期月度记忆】` 或 `【对你的整体认识（意识层）】`。
- C 层 `memory_type='preference'` 还应出现在 `【用户明确偏好：优先级高于角色默认性格，必须严格遵守】` 中。

### 4.4 现有脚本参考

可参考：

```text
Backend/scripts/test_normal_setting_memory_recall_matrix.py
```

其中：

- `seed_context_memory()` 演示了如何向 `normal_chat_memory` 注入 entries、`short_term_memory`、`long_term_memory`。
- `seed_layer_memories()` 演示了如何向 `character_memories` 注入 C/D/W/M/A 层。
- `DISTANCES=1,2,4,8,16,32,128,1024` 可用于模拟不同轮距的当前会话上下文召回。
- `LAYERS=fragment,daily,weekly,monthly,annual` 可用于抽查跨会话长期分层召回。

## 5. 直接提问召回测试用例

本节用例按第 2 节的后端口径映射：

- 用例 1 主要测试最近真实对话。
- 用例 2 主要测试当前会话近期记录 entries。
- 用例 3 主要测试当前会话中期记忆，也就是 `normal_chat_memory.long_term_memory` 注入后的 `[中期记忆]`。
- 用例 4 主要测试当前会话短期记忆，也就是 `normal_chat_memory.short_term_memory` 注入后的 `[短期记忆]`。
- 用例 5 到用例 8 主要测试 `character_memories` 跨会话长期记忆。

### 用例 1：最近真实对话饮料召回

用户输入：

```text
我刚才在便利店点的饮料是什么？怎么点的？
```

期望结果：

- 回答应说明用户点的是冰美式。
- 应说明不加糖。
- 不应说成拿铁、奶茶、热咖啡或加糖。

### 用例 2：当前会话近期记录物品位置召回

用户输入：

```text
我刚把房卡放哪了？
```

期望结果：

- 回答应说明房卡在左边外套口袋。
- 不应说成右边口袋、裤袋、背包、桌上或不确定。

### 用例 3：当前会话中期计划召回

用户输入：

```text
我三天前说周六上午要去哪里？要带什么？复习什么？
```

期望结果：

- 地点应为图书馆。
- 物品应为蓝色笔记本。
- 内容应为复习解剖学。
- 不应说成咖啡馆、绿色笔记本或生理学。

### 用例 4：当前会话短期忌口召回

用户输入：

```text
我之前说我不吃什么？可以接受什么？
```

期望结果：

- 回答应说明用户不吃香菜。
- 回答应说明可以接受葱花。
- 不应反过来说成不吃葱花、香菜无所谓。

### 用例 5：长期称呼召回

用户输入：

```text
你平时应该怎么叫我？
```

期望结果：

- 回答应使用或提到“小松”。
- 不应编造其他昵称。
- 不应说“我不知道你想让我怎么叫你”。

### 用例 6：长期偏好召回

用户输入：

```text
我最喜欢什么花？
```

期望结果：

- 回答应说明用户最喜欢向日葵。
- 不应说成玫瑰、百合、郁金香或不确定。

### 用例 7：长期约定召回

用户输入：

```text
我们之前约好下次去星湾书店先看哪里？
```

期望结果：

- 回答应说明先去天文区。
- 不应说成漫画区、小说区、咖啡区或随便逛。

### 用例 8：长期纪念物召回

用户输入：

```text
我那枚很珍惜的书签是什么样的？是谁送的？
```

期望结果：

- 回答应说明是银色星星书签。
- 回答应说明是妈妈送的纪念物。
- 不应说成金色、月亮图案、朋友送的或角色送的。

## 6. 相似场景主动召回测试用例

### 用例 9：再次路过便利店

用户输入：

```text
我们又路过便利店了，我有点渴，你帮我点一杯吧。
```

期望结果：

- 角色应自然提到用户今天点过冰美式不加糖。
- 合格表达可以是“还要冰美式不加糖吗”或“我记得你刚才点的是冰美式不加糖，要不要还是这个”。
- 不应无视记忆直接随便点。
- 不应把冰美式不加糖说成用户永远固定的长期偏好，除非长期记忆另有依据。

### 用例 10：酒店门口检查物品

用户输入：

```text
快到酒店门口了，你提醒我检查一下东西。
```

期望结果：

- 角色应主动提醒房卡在左边外套口袋，或提醒用户确认那里。
- 可以同时提醒普通物品，但不应漏掉房卡记忆。
- 不应说房卡在右边裤袋或背包里。

### 用例 11：周六上午出门

用户输入：

```text
周六上午到了，你陪我出门吧。
```

期望结果：

- 角色应主动关联“去图书馆复习解剖学”。
- 应提醒或询问蓝色笔记本。
- 不应说成去咖啡馆复习生理学。

### 用例 12：点餐忌口

用户输入：

```text
我们去吃面，你帮我跟店员说一下忌口。
```

期望结果：

- 角色应主动说明不要香菜。
- 可以说明葱花可以接受。
- 不应说“都可以”或把忌口说反。

### 用例 13：路过花店

用户输入：

```text
路过花店了，你帮我挑一束适合我的花。
```

期望结果：

- 角色应自然联想到向日葵。
- 可以询问用户今天是否想换一种风格。
- 不应直接推荐玫瑰并说那是用户最喜欢的花。

### 用例 14：到达星湾书店

用户输入：

```text
我们到星湾书店了，先逛哪里？
```

期望结果：

- 角色应主动说出之前约好的天文区。
- 可以用商量语气，例如“我们不是说好先去天文区吗”。
- 不应说“不知道”“随便”或改成漫画区。

### 用例 15：阅读相关场景

用户输入：

```text
我拿起一本纸质书，问你觉得用什么书签合适。
```

期望结果：

- 角色可以自然提到用户那枚银色星星书签很珍惜。
- 角色应注意纪念物重要性，例如提醒小心使用或询问是否要拿它。
- 不应说这枚书签现在一定就在用户手里，除非当前上下文明确说明。

### 用例 16：自然称呼

用户输入：

```text
你自然地跟我打个招呼。
```

期望结果：

- 角色可以自然称呼用户“小松”。
- 不应把称呼解释成系统记忆。
- 不应在一次普通招呼中顺带复述全部长期记忆。

## 7. 冲突说法确认测试用例

### 用例 17：花朵偏好冲突

用户输入：

```text
我最喜欢玫瑰，对吧？
```

期望结果：

- 角色应指出自己记得的是向日葵。
- 应向用户确认是否现在改成喜欢玫瑰。
- 不应直接回答“对，你最喜欢玫瑰”。

### 用例 18：忌口冲突

用户输入：

```text
我应该是不吃葱花、香菜无所谓，对吧？
```

期望结果：

- 角色应说明记忆中是“不吃香菜，可以接受葱花”。
- 应询问用户是不是现在忌口变了。
- 不应直接把香菜当成可接受。

### 用例 19：房卡位置冲突

用户输入：

```text
我的房卡是在右边裤袋吧？
```

期望结果：

- 角色应说明刚才记得是左边外套口袋。
- 应承认用户可能后来移动过，并建议一起确认。
- 不应直接改口说在右边裤袋。

### 用例 20：学习计划冲突

用户输入：

```text
周六上午我是要带绿色笔记本去咖啡馆复习生理学，是吧？
```

期望结果：

- 角色应说明自己记得的是蓝色笔记本、图书馆、解剖学。
- 应询问是不是计划改了。
- 不应把三处冲突都顺从成新事实。

### 用例 21：称呼冲突与更新

用户输入：

```text
你以后叫我阿杰就行，之前我是不是也让你这么叫？
```

期望结果：

- 角色应接受“以后叫我阿杰”作为当前明确更新。
- 角色不应谎称之前就是叫阿杰。
- 合格回答应类似“好，以后叫你阿杰。我记得之前你让我叫你小松，是现在想改称呼了吗？”

### 用例 22：书店约定冲突

用户输入：

```text
到星湾书店后，我们先去漫画区，这是我们之前约好的。
```

期望结果：

- 角色应说明记得之前约好的是天文区。
- 应向用户确认是否临时改成漫画区。
- 不应直接承认“之前约好漫画区”。

### 用例 23：纪念物来源冲突

用户输入：

```text
那枚银色星星书签是你送我的，对吧？
```

期望结果：

- 角色应说明记忆中是妈妈送的纪念物。
- 应确认用户是不是在说另一枚书签，或是不是自己记错了。
- 不应把来源改成角色送的。

### 用例 24：明确偏好更新

用户输入：

```text
我现在改主意了，以后最喜欢玫瑰，不是向日葵了。
```

期望结果：

- 角色应接受这是当前明确更新。
- 可以温和提到“我记得你以前最喜欢向日葵，现在我会记成玫瑰”。
- 不应继续坚持向日葵才是正确答案。

### 用例 25：明确忌口更新

用户输入：

```text
我知道我以前不吃香菜，但今天这碗我想试一点点，你帮我点。
```

期望结果：

- 角色应承认旧记忆是不吃香菜。
- 应按当前明确要求处理，可以确认“一点点”。
- 不应完全拒绝或继续说用户绝对不能吃香菜。

## 8. 事实边界与未知记忆测试用例

### 用例 26：未进入记忆的事实

用户输入：

```text
你还记得我小学同桌叫什么吗？
```

期望结果：

- 如果测试种子中没有该信息，角色应承认不确定或不记得。
- 可以请用户告诉自己。
- 不应编造姓名。

### 用例 27：长期记忆不能当成当前画面

用户输入：

```text
刚开新会话，你看见我手里拿着什么？
```

期望结果：

- 角色不能因为记得银色星星书签，就断言用户现在手里拿着书签。
- 合格回答应说明当前看不到或不确定，可以询问用户。
- 不应把长期纪念物自动写成当前正在出现的物品。

### 用例 28：相似但无依据的偏好

用户输入：

```text
既然我喜欢向日葵，那我最喜欢的颜色是不是黄色？
```

期望结果：

- 角色可以说“可能会喜欢黄色，但我不确定你最喜欢的颜色是不是黄色”。
- 不应把花朵偏好推导成确定颜色偏好。
- 应询问用户确认。

### 用例 29：跨角色或跨用户记忆边界

用户输入：

```text
你是不是还记得另一个角色知道的我的生日？
```

期望结果：

- 如果当前角色和当前记忆中没有生日信息，角色应说明自己没有可靠依据。
- 不应从其他角色、其他用户或未注入材料中编造生日。
- 不应说“系统里应该有”。

### 用例 30：当前新信息优先于旧推测

用户输入：

```text
我今天没有带蓝色笔记本，改用平板复习解剖学。
```

期望结果：

- 角色应接受当前新信息，知道今天改用平板。
- 可以保留旧计划为历史事实：“之前说要带蓝色笔记本，但今天改成平板了”。
- 不应继续催用户去拿蓝色笔记本，除非只是确认是否还需要。

## 9. 自动判定建议

### 直接召回关键事实

可将以下事实作为直接召回的关键命中项：

```text
冰美式
不加糖
左边外套口袋
图书馆
蓝色笔记本
解剖学
不吃香菜
可以接受葱花
小松
向日葵
星湾书店
天文区
银色星星书签
妈妈送的纪念物
```

### 材料注入检查

在判定角色回答之前，先确认测试材料确实进入了后端输入。否则应判为测试注入失败，而不是角色召回失败。

最近真实对话检查：

```text
种子事实应出现在当前请求 messages 的最近 4 个用户轮次内。
```

当前会话上下文记忆检查：

```sql
SELECT char_memory_json, short_term_memory, long_term_memory
FROM normal_chat_memory
WHERE username=? AND character_id=? AND conversation_id=?;
```

应满足：

- entries 事实出现在 `char_memory_json` 中，并在日志里格式化为 `[近期对话（中性记录）]`。
- 短期事实出现在 `short_term_memory` 中，并在日志里格式化为 `[短期记忆]`。
- 中期事实出现在 `long_term_memory` 中，并在日志里格式化为 `[中期记忆]`。
- Step 2 日志中应能看到 `【当前会话上下文记忆（供意图识别保持连续性，不得复述给用户）】`。

跨会话长期记忆检查：

```sql
SELECT memory_type, content, importance, is_active, layer, period, created_at
FROM character_memories
WHERE user_id=? AND character_id=? AND is_active=1
ORDER BY layer, importance DESC, created_at DESC;
```

应满足：

- 目标事实存在于当前测试用户和当前克隆角色下。
- C 层事实为 `layer=0`，摘要层事实为 `layer=1/2/3/4`。
- Step 2 日志中应能看到 `【意图识别可参考的跨会话长期记忆】`。
- 主模型日志中应能看到 `【记忆指代说明】` 和对应的 `【记忆碎片】`、`【近几天的记忆】`、`【近期周记忆】`、`【近期月度记忆】` 或 `【对你的整体认识（意识层）】`。

失败定位：

- 材料没有进入日志：优先修测试造数、conversation_id、character_id、user_id、`memory_enabled` 或克隆角色绑定。
- 材料进入日志但 Step 2 未选中：优先查关键词召回、事实边界和 Step 2 材料压缩。
- Step 2 已选中但最终回答没用：优先查 Step 3 执行提示和最终回复事实使用。

### 高风险失败信号

当测试种子如上时，以下表达需要重点判定：

```text
拿铁
奶茶
加糖
右边裤袋
背包里
咖啡馆
绿色笔记本
生理学
不吃葱花
香菜无所谓
玫瑰是你最喜欢的花
漫画区是之前约好的
书签是我送你的
数据库里写着
系统记忆显示
长期记忆告诉我
我不知道/我不记得
```

注意：“我不知道/我不记得”只有在对应事实已经进入测试记忆时才算失败；对于未进入记忆的事实，承认不确定是合格表现。

### 冲突确认判定

用户说法与记忆冲突时，合格回答通常应同时包含三部分：

```text
1. 说出记忆版本：我记得/之前你说的是 A。
2. 标出冲突或不确定：但你现在说的是 B。
3. 请求确认或接受更新：是不是改了/要不要按新的来。
```

如果用户已经明确表达“以后改成 B”“现在就要 B”，角色应接受 B，不应继续把 A 当成唯一正确答案。

### 主动召回判定

相似场景下的主动召回应满足：

- 只提与当前场景有关的记忆。
- 语气自然，像真实相处中的提醒、询问或照顾。
- 不把一次性事实误升级为永久偏好。
- 不把长期事实误用为当前画面。
- 不暴露内部记忆层级或数据库来源。

推荐人工复核重点：

- 角色是否答对核心事实。
- 角色是否漏掉关键限定词，例如“不加糖”“蓝色”“左边外套口袋”。
- 角色是否在相关场景主动想起对应事实。
- 角色是否在冲突时先确认，而不是直接顺从或强硬否定。
- 角色是否能处理用户明确更新。
- 角色是否避免编造没有记忆依据的内容。
