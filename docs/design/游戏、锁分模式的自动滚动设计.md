# 游戏、锁分模式的自动滚动设计

本文记录 Android App 游戏模式和锁分模式的消息列表自动滚动设计。这里的“游戏模式”和“锁分模式”指角色扮演类对话界面，不覆盖普通对话模式。

## 和普通模式的核心区别

游戏、锁分模式比普通对话模式更简单：

1. 没有语音消息，也没有语音转写展开后的局部露出滚动。
2. 每一次角色只回复一条消息，不需要处理同一轮里多条助手消息连续入列。
3. 用户发送消息后会先出现角色打字动画，之后打字动画被角色回复替换。
4. 角色回复通常很长，自动滚动目标不是消息列表底部，而是让最后一条角色消息的顶部靠近好感度胶囊。

## 设计目标

游戏、锁分模式的自动滚动应遵守三条原则：

1. 用户发送消息后，视角跟随到打字动画，让打字动画底部露在输入栏上方。
2. 用户仍在当前回合尾部时，角色回复到达后，视角定位到角色回复开头，让最后一条消息顶部靠近好感度胶囊。
3. 从角色列表进入消息列表时，也优先展示最后一条消息的开头，而不是直接滚到底部。

这个设计是为了让用户从长回复的开头开始阅读。游戏、锁分模式里角色回复往往是长段落，如果直接滚到底部，用户会先看到回复末尾，阅读体验会很差。

## 基础锚点

游戏、锁分模式需要两个不同的自动滚动锚点。

### 1. 顶部阅读锚点

顶部阅读锚点用于展示角色长回复的开头。

定义：

- 锚点位置在好感度胶囊下方，保留少量间距。当前实现的目标位置是“好感度胶囊高度 + 8dp”。
- 最后一条角色消息的顶部应尽量贴近这个锚点。
- 如果最后一条消息本身太靠近列表顶部，或者列表内容不足以滚到目标位置，可以停在列表可滚动边界。
- 列表需要为游戏、锁分模式的最后一条角色消息提供少量额外尾部可滚动余量，避免最后一个长消息因为底部边界完全无法向上靠近锚点；这笔余量只取完整理论余量的一小部分，当前为理论余量的五分之一，防止消息底部留下过大的空白。
- 尾部余量只在顶部阅读锚点目标下启用。角色打字动画阶段不使用这笔余量，避免输入栏上方出现不必要空白。
- 如果滚动后因为复杂消息内容、选项区、好感度胶囊测量或 Compose 二次布局导致顶部位置有轻微偏移，需要在短时间内做小幅修正，让最后一条角色消息顶部重新靠近锚点。

适用场景：

- 从角色列表进入游戏或锁分消息列表。
- 角色回复新消息到达，且用户没有离开当前回合尾部去看历史。
- 回前台补拉后，如果确认有角色新回复需要展示。

### 2. 底部打字锚点

底部打字锚点用于用户发送后展示角色打字动画。

定义：

- 打字动画底部应露在输入栏或底部遮挡上方。
- 打字动画和输入栏之间保留自然间距，避免贴边。
- 这里的目标是“看见角色正在输入”，不是展示最后一条长回复的开头。

适用场景：

- 用户发送消息成功，本地追加用户消息，并出现角色打字动画。
- 角色回复尚未返回，但打字动画状态发生尺寸变化。

## 自动滚动入口

### 1. 从角色列表进入消息列表

进入游戏或锁分消息列表后，如果已有历史消息，应定位到最新一条消息的顶部阅读锚点。

规则：

- 如果最后一条消息是角色消息，让这条消息顶部靠近好感度胶囊。
- 如果最后一条消息是用户消息，并且当前正在等待角色回复，可以滚到打字动画底部。
- 如果没有消息，不执行消息列表自动滚动。
- 初始定位可以在加载遮罩揭开前完成，避免用户看到滚动过程。
- 初始加载遮罩只绑定角色和模式，不绑定 `conversationId`。`conversationId` 从本地临时值落定为服务端值时，不应重建遮罩，也不应触发第二次初始定位。
- 初始定位前如果需要好感度胶囊高度，应等待胶囊完成测量；超过短等待窗口仍未测到时，使用已有高度继续定位，不能让遮罩无限停留。
- 非打字等待场景进入页面时，初始定位直接走顶部阅读锚点；打字等待场景才走打字动画底部锚点。
- 初始加载过程中应只出现一次加载动画和一次消息展示稳定过程，不能出现“加载动画 -> 消息闪现 -> 再加载动画 -> 再消息展示”的多轮闪烁。

### 2. 用户发送消息

用户发送消息后，消息列表会追加用户消息，并显示角色打字动画。

规则：

- 自动滚动目标是打字动画底部，不是消息列表底部，也不是最后一条用户消息顶部。
- 如果输入栏、键盘或底部面板造成遮挡，打字动画底部应停在可见区域底部上方。
- 这条滚动可以覆盖用户此前是否在看历史，因为发送动作表示用户进入当前回合。
- 发送后不等待角色回复；打字动画出现后就可以滚动到打字动画底部。
- 游戏、锁分模式里用户消息和空的角色占位消息可能同一帧追加；这时最后一条看起来是角色占位，但语义仍是“用户刚发送并进入打字等待”，必须使用打字动画底部锚点。
- 用户发送后的打字动画阶段不启用顶部阅读锚点尾部余量。

### 3. 角色回复到达

角色回复到达后，打字动画被一条角色消息替换。

规则：

- 自动滚动目标切换为顶部阅读锚点。
- 最后一条角色消息的顶部靠近好感度胶囊。
- 不滚到这条角色消息的底部。
- 如果用户在角色回复返回前已经滑开，导致列表看不到上一帧的最后一条消息或打字动画，应认为用户正在看历史，不自动抢回到新回复。
- “用户仍在当前回合尾部”的判断使用上一帧最后一条 item 是否可见，而不是使用普通的接近底部状态。只要上一帧最后 item 不可见，就按看历史处理。
- 如果用户正在触摸列表，或者自动跟随被用户拖动、引用跳转、语音转写等主动行为抑制，也不在角色回复到达时抢滚。
- 因为每回合只会有一条角色回复，不需要普通模式的多条助手消息防抖合并。
- 如果角色消息仍在进行逐字显示或打字效果，初始定位应以消息容器顶部为准，不随正文逐字增长反复滚动。
- 角色回复从打字状态结束到消息内容稳定之间允许有一个短延迟，再执行顶部阅读锚点滚动；滚动后还要做小幅锚点修正，避免长消息首帧高度变化造成锚点偏移。

### 4. 回前台或后台刷新

回前台补拉或后台刷新时，需要区分是否出现角色新回复。

规则：

- 如果没有新增可见消息，不改变列表位置。
- 如果新增的是角色回复，并且这条回复属于当前回合，同时用户仍在当前回合尾部，应定位到顶部阅读锚点。
- 如果用户已经看不到最后一条消息，应认为用户在看历史，只更新数据，不改变列表位置。
- 如果只是状态字段、好感度、任务状态等变化，不触发消息列表自动滚动。
- 如果用户正在手动拖动列表，刷新完成时不抢手势；应恢复刷新前的可见锚点，而不是等用户松手后补一次兜底滚动。
- 刷新等价判断要比较刷新前后的可见消息列表。仅有不会影响布局的元数据变化时，不触发顶部锚点定位，也不重建加载遮罩。
- 如果角色回复在 App 后台期间已经到达，系统通知或后台 outbox 补拉可能会先把当前聊天页数据更新掉。聊天页需要使用 `ON_PAUSE` 时记录的最后一条可见性快照：离开时最后一条可见且回前台后消息尾部变化，才自动定位到最后一条角色消息顶部锚点；离开时看不到最后一条，则仍按看历史处理。

## 可见稳定性和动画去重

游戏、锁分模式的自动滚动和消息进场动画要分开处理，但二者会共同影响用户是否看到闪烁。

规则：

- 初始加载完成时，把当前所有历史消息登记为已知消息，不播放进场动画。
- 初始加载完成后，只有真正追加到列表尾部的新消息才播放发送或出现动画。
- 如果角色回复到达只是把本地空占位消息替换为正式角色消息，或者后台刷新用服务端消息替换本地同位置消息，这类同长度更新只登记为已知，不重新播放上一条用户消息和本次角色消息的进场动画。
- 同一页面生命周期里，加载遮罩不因为 `conversationId` 落定而重建；这样从角色列表进入消息列表时，只会有一次加载动画和一次消息展示过程。
- 动画去重不能改变自动滚动目标：打字阶段仍看打字动画底部，回复到达后仍看角色消息顶部。

## 底部遮挡处理

游戏、锁分模式仍然会受到输入栏、键盘和底部面板遮挡影响，但遮挡处理只负责保证当前目标可见，不负责改变目标类型。

规则：

- 当前目标是打字动画底部时，遮挡增加要让打字动画底部继续保持在可见区域内。
- 当前目标是角色消息顶部时，遮挡变化不应把目标改成滚到底部。
- 键盘关闭且没有面板接管时，底部栏可以瞬间归位。
- 键盘切换到表情面板、快捷回复或更多面板时，只按键盘高度和面板高度的差值移动，不能经过 0 高度中间态。

## 不需要继承的普通模式逻辑

游戏、锁分模式不需要下面这些普通模式逻辑：

- 语音消息转写展开后的局部露出。
- 多条助手消息 200 毫秒防抖合并。
- 普通模式那套“角色回复后继续滚到底部”的自动跟随判断。
- 角色回复后滚到底部。

这些逻辑要么不存在对应场景，要么会和长回复从开头阅读的目标冲突。

## 硬性要求

1. 从角色列表进入消息列表时，如果有最后一条消息，应优先让最后一条消息顶部靠近好感度胶囊。
2. 用户发送消息后，应自动滚动到角色打字动画底部。
3. 角色回复到达后，如果用户仍在当前回合尾部，应自动滚动到最后一条角色消息顶部，而不是滚到底部。
4. 角色回复逐字显示期间，不应因为正文高度增长反复把视角拉到底部。
5. 游戏、锁分模式每轮只处理一条角色回复，不引入普通模式的多助手消息防抖。
6. 底部遮挡补偿不能改变当前滚动目标类型；打字动画仍按底部锚点，角色回复仍按顶部锚点。
7. 如果用户已经滑开并且看不到最后一条消息，应尊重用户正在看历史的状态，新回复只更新数据，不主动滚动。
8. 顶部阅读锚点需要有少量尾部滚动余量；如果最后一条角色消息已经是列表最后一个 item，应能向好感度胶囊方向靠近，但不能为了强行完全贴齐而在底部制造大块空白。
9. 顶部阅读锚点的目标位置是好感度胶囊下方 8dp；定位后如果布局继续稳定，允许有限次数的小幅修正，但不能转成滚到底部。
10. 初始加载遮罩不能因为 `conversationId` 落定而重建；从角色列表进入消息列表只能看到一次加载动画。
11. 同长度消息替换不能触发旧消息进场动画重放，尤其不能让上一条用户消息和本次角色消息在回复返回时再次播放发送动画。
12. 回前台自动跟随必须消费离开时的最后一条可见性快照；如果离开前最后一条不可见，后台期间到达的新回复不能抢走历史阅读位置。

## 伪代码

```kotlin
class GameChatScrollController {

    enum class AutoScrollTarget {
        None,
        TypingIndicatorBottom,
        LastMessageTopNearAffinityCapsule
    }

    var currentTarget: AutoScrollTarget = AutoScrollTarget.None
    var initialLoadingOverlayDismissed: Boolean = false
    var lastKnownCanSeeLastItem: Boolean = false
    var tailScrollReservePx: Int = 0
    var foregroundResumeSnapshot: ForegroundResumeSnapshot? = null

    val topAnchorGapPx: Int = dp(8)
    val minimumTopAnchorReservePx: Int = dp(104)
    val topAnchorReserveRatio: Int = 5

    data class ForegroundResumeSnapshot(
        val characterId: String,
        val mode: String,
        val conversationId: String?,
        val messageCount: Int,
        val lastMessageKey: String?,
        val wasLastMessageVisibleOnPause: Boolean,
        val resumeRequestedAtMs: Long = 0
    )

    fun onEnterMessageList(messages: List<Message>, typingVisible: Boolean, conversationIdSettled: Boolean) {
        if (messages.isEmpty()) return

        // 初始遮罩的生命周期由角色 + 模式控制，不由 conversationId 控制。
        // conversationId 在同一页面内从空值落定时，只更新数据归属，
        // 不能重建遮罩，也不能再次执行初始定位。
        if (initialLoadingOverlayDismissed && conversationIdSettledOnlyChanged()) {
            return
        }

        waitForAffinityCapsuleHeightOrTimeout()

        currentTarget = if (typingVisible && messages.last().isFromUserOrBlankAssistantPlaceholder()) {
            AutoScrollTarget.TypingIndicatorBottom
        } else {
            AutoScrollTarget.LastMessageTopNearAffinityCapsule
        }

        applyCurrentTarget(animated = false)
        initialLoadingOverlayDismissed = true
        markMessagesKnownWithoutEntranceAnimation(messages)
    }

    fun onUserMessageSent() {
        // 用户发送后，角色打字动画会出现在列表尾部。
        // 这里的目标是让用户看见“角色正在输入”，所以使用底部锚点。
        currentTarget = AutoScrollTarget.TypingIndicatorBottom
        tailScrollReservePx = 0
        scrollTypingIndicatorBottomToVisibleBottom()
    }

    fun beforeMessageOrStreamingStateChanges() {
        // 角色回复到达前记录上一帧最后一条 item 是否可见。
        // 这个判断比“是否接近底部”更符合游戏/锁分模式：
        // 只要用户看不到最后一条消息或打字动画，就认为用户在看历史。
        lastKnownCanSeeLastItem = canSeeLastItem()
    }

    fun onAppPause(characterId: String, mode: String, conversationId: String?) {
        foregroundResumeSnapshot = ForegroundResumeSnapshot(
            characterId = characterId,
            mode = mode,
            conversationId = conversationId,
            messageCount = currentMessages().size,
            lastMessageKey = currentMessages().lastOrNull()?.stableKey,
            wasLastMessageVisibleOnPause = canSeeLastItem()
        )
    }

    fun onAppResume(characterId: String, mode: String, conversationId: String?) {
        val snapshot = foregroundResumeSnapshot ?: return
        if (!snapshot.wasLastMessageVisibleOnPause) return
        if (snapshot.characterId != characterId || snapshot.mode != mode) {
            foregroundResumeSnapshot = null
            return
        }
        if (
            snapshot.conversationId != null &&
            conversationId != null &&
            snapshot.conversationId != conversationId
        ) {
            foregroundResumeSnapshot = null
            return
        }
        foregroundResumeSnapshot = snapshot.copy(resumeRequestedAtMs = nowMs())
    }

    fun onForegroundResumeSettled() {
        val snapshot = foregroundResumeSnapshot ?: return
        if (snapshot.resumeRequestedAtMs <= 0) return
        if (initialLoadingOverlayVisible() || isLoadingHistory() || isBackgroundRefreshing()) return

        val currentLastKey = currentMessages().lastOrNull()?.stableKey
        val tailChanged =
            currentMessages().size > snapshot.messageCount ||
                (currentMessages().size == snapshot.messageCount && currentLastKey != snapshot.lastMessageKey)
        if (!tailChanged) {
            if (nowMs() - snapshot.resumeRequestedAtMs > 3500) {
                foregroundResumeSnapshot = null
            }
            return
        }
        if (userIsTouchingList() || autoFollowSuppressed()) return

        foregroundResumeSnapshot = null
        currentTarget = AutoScrollTarget.LastMessageTopNearAffinityCapsule
        scrollMessageTopNearAffinityCapsule(currentMessages().lastAssistantId(), animated = false)
    }

    fun onCharacterReplyArrived(reply: Message) {
        // 游戏、锁分模式一轮只返回一条角色消息。
        // 长回复应从开头开始读，所以定位到消息顶部锚点。
        if (!reply.isFromCharacter) return

        // 如果用户已经滑开，上一帧最后一条消息或打字动画不在可见区域，
        // 说明用户正在看历史；此时新回复不能抢走阅读位置。
        if (!lastKnownCanSeeLastItem || userIsTouchingList() || autoFollowSuppressed()) {
            currentTarget = AutoScrollTarget.None
            return
        }

        currentTarget = AutoScrollTarget.LastMessageTopNearAffinityCapsule
        launchAfter(150.milliseconds) {
            scrollMessageTopNearAffinityCapsule(reply.id, animated = true)
        }
    }

    fun onMessagesChanged(oldMessages: List<Message>, newMessages: List<Message>) {
        // 只有真正追加到尾部的新消息播放进场动画。
        // 空角色占位被正式回复替换、后台刷新用服务端消息替换本地同位置消息，
        // 都属于同长度更新，只登记为已知消息，不重放上一条用户消息和角色消息动画。
        if (newMessages.size > oldMessages.size) {
            animateOnlyTailAppendedMessages(oldMessages, newMessages)
        } else {
            markMessagesKnownWithoutEntranceAnimation(newMessages)
        }
    }

    fun onTypingIndicatorSizeChanged() {
        // 打字动画仍是当前目标时，动画尺寸变化只需要保持底部可见。
        // 不要切换成滚到底部，也不要影响角色回复顶部锚点。
        if (currentTarget == AutoScrollTarget.TypingIndicatorBottom) {
            scrollTypingIndicatorBottomToVisibleBottom()
        }
    }

    fun onCharacterReplyTextLayoutChanged(replyId: String) {
        // 角色回复逐字显示或正文高度增长时，不反复滚到底部。
        // 如果需要修正，也只允许保持消息顶部靠近好感度胶囊。
        if (currentTarget == AutoScrollTarget.LastMessageTopNearAffinityCapsule) {
            keepMessageTopNearAffinityCapsule(replyId)
        }
    }

    fun onBottomObstructionChanged() {
        // 底部遮挡只修正当前目标的可见性，不改变目标类型。
        when (currentTarget) {
            AutoScrollTarget.TypingIndicatorBottom ->
                scrollTypingIndicatorBottomToVisibleBottom()

            AutoScrollTarget.LastMessageTopNearAffinityCapsule ->
                keepLastMessageTopNearAffinityCapsule()

            AutoScrollTarget.None -> Unit
        }
    }

    private fun scrollTypingIndicatorBottomToVisibleBottom() {
        val typingBottomPx = typingIndicatorBottomInList()
        val visibleBottomPx = listVisibleBottomAboveInputBar()
        val desiredBottomPx = visibleBottomPx - naturalBottomGapPx
        val deltaPx = typingBottomPx - desiredBottomPx

        if (deltaPx > 0) {
            scrollBy(deltaPx)
        }
    }

    private fun scrollMessageTopNearAffinityCapsule(messageId: String, animated: Boolean = false) {
        // 最后一条角色消息通常也是列表最后一个 item。
        // 如果列表尾部没有额外可滚动空间，LazyColumn 会在底部边界停止，
        // 导致消息顶部无法靠近好感度胶囊。
        // 因此在执行顶部锚点滚动前，需要确保尾部有一段只服务于阅读锚点的 reserve。
        // reserve 不能按完整理论高度全量加入，否则短回复或选项较少时底部会出现过大呼吸空间。
        // 注意：打字动画阶段不能开启这段 reserve，否则会让打字动画和输入栏之间出现大空白。
        ensureTailScrollReserveForTopAnchor(messageId)

        val messageTopPx = messageTopInList(messageId)
        val desiredTopPx = affinityCapsuleBottomPx + topAnchorGapPx
        val deltaPx = messageTopPx - desiredTopPx

        if (animated) {
            animateScrollBy(deltaPx)
        } else {
            scrollBy(deltaPx)
        }
        repairTopAnchor(messageId)
    }

    private fun keepMessageTopNearAffinityCapsule(messageId: String) {
        val messageTopPx = messageTopInList(messageId)
        val desiredTopPx = affinityCapsuleBottomPx + topAnchorGapPx
        val driftPx = messageTopPx - desiredTopPx

        if (abs(driftPx) > topAnchorTolerancePx) {
            scrollBy(driftPx)
        }
    }

    private fun repairTopAnchor(messageId: String) {
        // 复杂长消息、选项区和好感度胶囊测量可能在滚动后继续稳定。
        // 只允许有限次数的小幅修正，目标仍是消息顶部锚点，不能改成滚到底部。
        repeat(4) {
            waitNextLayoutFrame(32.milliseconds)
            keepMessageTopNearAffinityCapsule(messageId)
        }
    }

    private fun ensureTailScrollReserveForTopAnchor(messageId: String) {
        // 只在顶部阅读锚点启用。
        // TypingIndicatorBottom 目标仍然依赖输入栏上方的可见底部，
        // 不应因为阅读锚点 reserve 改变底部对齐。
        if (currentTarget != AutoScrollTarget.LastMessageTopNearAffinityCapsule) return

        val messageHeightPx = messageHeightInList(messageId)
        val viewportBottomPx = listViewportBottomPx()
        val desiredTopPx = affinityCapsuleBottomPx + topAnchorGapPx

        // 当最后一个 item 较短或中等长度时，底部边界会限制最大滚动距离。
        // reserve 至少要覆盖“视口底部 - 消息高度 - 目标顶部”的差值，
        // 这样 scrollBy 才有空间把消息顶部推到 desiredTopPx。
        val requiredReservePx = viewportBottomPx - messageHeightPx - desiredTopPx

        // 保留一个最小值是为了首帧尚未测到消息高度时也有基础余量；
        // 后续拿到真实高度后再按 requiredReservePx 修正。
        tailScrollReservePx =
            max(requiredReservePx, minimumTopAnchorReservePx).coerceAtLeast(0) / topAnchorReserveRatio
    }
}
```
