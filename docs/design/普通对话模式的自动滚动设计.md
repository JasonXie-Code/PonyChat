# 普通对话模式的自动滚动设计

> 文档状态：2026-08-09 已复核。本文作为设计或测试规范继续保留；条目是否已实现以 `docs/PROJECT_STATUS.md` 和代码为准。

本文记录 Android App 普通对话模式的自动滚动设计。这里的“普通对话模式”指常规聊天界面，不覆盖剧情模式和锁分剧情模式的特殊滚动。

## 设计目标

普通对话的自动滚动应遵守两条原则：

1. 用户在底部阅读最新消息时，新消息到达后自动跟随到底部。
2. 用户已经手动查看历史时，不应被后续布局变化、刷新、回前台等行为拉回底部。

## 基础判断

普通模式判断用户是否在看历史，只看最后一条信息是否可见：

- 最后一条信息可见：认为用户还在看最新位置，可以自动跟随。
- 最后一条信息不可见：认为用户正在看历史，不自动跟随。

当前设计里，“最后一条信息是否可见”的含义偏宽：最后一条信息只要还露出一部分，就会被视为可见。这个边界情况可以接受。

另外，如果新消息到达时用户手指正在操作消息列表，会跳过本次自动跟随，避免和用户手势冲突。这个只是一条即时保护，不用于判断用户是否在看历史。

### 判断快照和优先级

为了避免同一个事件在不同布局帧里得到不同结论，普通模式的滚动判断按下面的快照规则执行：

- 是否应该自动跟随，优先使用“数据变化前”的最后一条信息可见性作为快照。
- 真正执行滚动前，可以再次检查用户是否正在触摸消息列表；如果正在触摸，就跳过本次自动跟随，不在用户松手后补一次兜底滚动。
- 遮挡补偿不读取“是否在底部”状态，也不读取用户触摸状态；它只消费底部遮挡高度变化。
- 用户主动导航优先级最高，包括用户滚动历史、点击引用跳转、展开语音转写、左右切换页面等。自动跟随不能覆盖这些主动行为。

可以把普通模式里的位置变化分成三类：

| 类型 | 典型场景 | 是否滚到底部 | 是否受用户触摸影响 |
| --- | --- | --- | --- |
| 初始定位 | 首次进入聊天页展示最新窗口 | 是，只在遮罩存在时执行 | 不依赖触摸状态 |
| 自动跟随 | 助手新消息、刷新补拉到新消息 | 只有变化前最后一条可见时才滚到底部 | 执行时如果正在触摸则跳过 |
| 相对补偿 | 键盘、底部栏、扩展面板、关系页切换 | 否，只按遮挡变化量移动 | 不受触摸影响 |

## 自动滚动入口

### 1. 进入聊天页初始展示

当进入聊天页并且本地缓存或服务端返回的最新一页消息已经显示后，加载遮罩还没揭开前，会先滚到底部。这样用户进入对话时直接看到最新一页里的最新消息，滚动过程被遮罩盖住。

约束：

- 普通模式初始窗口是最新一页消息，不是从最旧消息开始加载。
- 本地缓存命中时，最多取缓存里的最近 50 条；没有缓存或需要服务端结果时，初始分页请求也是最新 50 条。
- 消息列表仍按旧到新排列，最新消息在列表底部。
- 更旧的消息只在用户向上滚到顶部附近时懒加载，每次加载 50 条并插入列表头部。
- 只在初始加载遮罩还存在时执行。
- 遮罩揭开后，普通对话过程中不再因为加载状态变化重复滚到底部。
- 初始加载遮罩的生命周期只绑定角色和模式，不绑定 `conversationId`。`conversationId` 从本地空值变成服务端值时，不能重建遮罩，也不能借机再做一次初始滚动。
- 回前台登记当前活跃会话时，只更新活跃状态和已读状态，不在这个入口触发历史重载或初始滚动。进入页面的历史加载由初始化流程负责。

### 2. 用户发送消息

当消息列表新增消息且最后一条是用户消息时，聊天页会滚到底部，确保刚发出的用户气泡露在输入栏上方。

这是用户主动发送消息带来的定位行为，可以覆盖“用户此前正在看历史”的状态。因为发送动作本身已经表达了用户回到当前对话尾部的意图。

约束：

- 发送完成后，刚发出的用户消息会成为最后一条信息；后续仍只按“最后一条信息是否可见”判断是否自动跟随。
- 不等待键盘或底部栏稳定；键盘、底部栏造成的遮挡位移由独立的遮挡补偿路径处理。
- 用户发送消息只通过这一条路径触发滚到底部。

### 3. 助手新消息到达

当普通模式新增助手消息时，如果新增前的最后一条信息被判断为可见，则进入自动跟随。这个判断只在消息入列前取一次快照，后续防抖等待期间不重新把“是否在底部”改写成别的含义。

当前策略：

- 使用 200 毫秒防抖。
- 200 毫秒内如果又有助手消息到达，会取消上一轮等待并重新计时。
- 例如第 0 毫秒到达一条助手消息，第 80 毫秒又到达一条，则滚动会延迟到约第 280 毫秒执行。
- 最终只在短时间连续到达的一组消息稳定后滚一次。
- 防抖执行前会再次检查用户触摸状态；如果执行时用户手指正在操作消息列表，则跳过本轮滚动，不等用户松手后补滚。

跳过条件：

- 用户手指正在操作消息列表。
- 新消息到达前，看不到最后一条信息。

### 4. 后台刷新、回前台补拉和服务端同步

聊天页展示本地缓存后，会在后台刷新服务端数据。刷新开始时会记录用户当时正在看的可见位置。

刷新结束后：

- 如果消息内容没有变化，不改变列表位置。
- 如果刷新前能看到最后一条信息，并且刷新后出现新消息、补齐消息或会改变可见消息布局的服务端数据替换，刷新完成后应自动滚到底部，继续展示最新位置。
- 如果刷新前看不到最后一条信息，即使刷新后有新消息、补齐消息或会改变可见消息布局的服务端数据替换，也不因为数据变化而滚到底部，应优先保持用户正在看的位置。
- 如果只是发送状态、已读状态、后台元数据等不影响当前可见内容尺寸和排序的字段变化，应尽量保留现有列表位置，不把它当成需要滚动的内容变化。
- 刷新前快照要保存当时的可见消息列表，而不是只保存数量、首条 key、末条 key 或末条角色。刷新后如果可见消息在身份和影响布局的字段上等价，就视为没有需要滚动的内容变化。
- 如果刷新完成时自动跟随被用户拖动、语音转写展开、引用跳转等主动行为抑制，即使刷新前最后一条可见，也应恢复刷新前的可见锚点，不抢回底部。

注意：回前台本身已经不再直接滚到底部；回前台触发的服务端补拉是否滚动，也只看补拉前最后一条信息是否可见。补拉前看得到最后一条信息则继续跟随，补拉前看不到最后一条信息则保持用户离开时的阅读位置。

如果消息在 App 后台期间已经到达，系统通知或后台 outbox 补拉可能会先把当前聊天页的数据更新掉。为了不丢失用户离开时的阅读意图，聊天页在 `ON_PAUSE` 时需要记录一个回前台快照：

- 记录角色、模式、会话、消息数量、最后一条消息 key，以及离开时最后一条消息是否可见。
- `ON_RESUME` 时，如果同一角色同一模式仍然打开，并且离开时最后一条消息可见，则挂起一次“回前台自动跟随请求”。
- 等当前刷新、补拉、初始遮罩都稳定后，如果消息尾部相比离开时发生变化，就消费这次请求：普通模式滚到底部，游戏/锁分模式滚到最后一条角色消息顶部锚点。
- 如果离开时看不到最后一条消息，说明用户在看历史；即使后台期间有系统通知和新消息，也不自动滚动。
- 如果回前台后几秒内消息尾部没有变化，丢弃这次请求，避免它误伤后续用户已经在前台时到达的新消息。

### 5. 输入栏、键盘、底部面板遮挡补偿

当键盘、底部输入栏或扩展面板改变底部遮挡高度时，消息列表只做遮挡补偿：底部栏多遮盖了多少当前可见内容，消息列表就上移多少；底部栏少遮盖了多少当前可见内容，消息列表就下移多少。这条路径不判断是否滚到底部。

规则：

- 从无遮挡进入遮挡时，先判断当前可见内容是否会被遮挡；如果会被遮挡，就上移实际被遮盖的距离。
- 当前可见内容包括消息内容，也包括列表滚到底部时保留的自然底部间距，不能让底部栏刚好贴住最后一条消息底边。
- 如果遮挡升起前最后可见内容已经贴近底部栏，并且两者之间有一段实际呼吸间距，遮挡升起后应尽量保持这段呼吸间距不变，而不是压缩到固定最小间距。只有这段间距仍处在底部呼吸区间内时才保留；如果内容离底部栏很远，说明用户并不在底部附近，不应因为保留大间距而额外上推历史内容。
- 初次判断“当前可见内容是否会被遮挡”时，只能使用当前布局帧的可见内容底部，不能拿历史帧里更靠下的内容底部做兜底或取最大值。当前布局帧里已经被旧底部栏裁掉、用户看不到的内容，也不能算作新键盘遮住的内容。否则用户停在历史消息时，键盘升起会误用旧底部坐标或旧裁剪外内容，把列表多推一段距离，形成输入栏上方的大块空白。
- 已经处于遮挡状态时，只看遮盖变化量：多遮盖多少就继续上移多少，少遮盖多少就下移多少。面板之间切换也按这个规则处理。
- 已经处于遮挡补偿状态时，正向遮挡差值必须在“当前内容是否会被遮挡”的可见性判断之前直接入账。可见性判断只适用于从无遮挡第一次进入遮挡的场景；如果面板已经遮住了底部内容，再从较矮面板切到较高键盘，继续拿当前可见内容做遮挡判断，会把“键盘比面板多出来的高度差”误判成不需要移动，导致消息被新键盘遮住。
- 计算遮挡区域顶部时必须使用底部浮层的总上移高度，包括键盘、表情面板、更多面板和键盘交接高度。不能只使用键盘 graphics 位移，否则表情面板这类通过布局上移的面板会被低估，导致消息被面板遮住。
- 键盘高度不能让底部输入栏和消息列表分别读取两套时序。输入栏的视觉位移、列表底部 padding、遮挡顶部和补偿位移必须使用同一次布局帧采样到的底部遮挡高度。否则快速升起或落下键盘时，输入栏可能已经按 IME draw-phase 到位，而消息列表还停在上一帧。
- 计算遮挡区域顶部时不能只信任输入栏视觉顶部坐标。键盘和底部面板交接的一帧里，输入栏视觉顶部可能仍是旧面板高度对应的位置；此时应同时根据当前合并后的遮挡高度推导遮挡顶部，并取更靠上的那个顶部作为本帧遮挡边界，避免一帧旧坐标把新增遮挡差值吞掉。
- 底部栏和消息内容必须使用同一个当帧遮挡高度做视觉运动：底部栏用该高度上移，消息列表升起避让时也先用同一帧计算出的补偿量做 `graphicsLayer` 向上视觉位移。真实 `LazyListState` 滚动可以在下一帧结算，但不能让用户看到“底部栏先到位、消息内容后一帧追上”的中间态。
- 遮挡减少时不能把整条消息列表先做向下 `graphicsLayer` 视觉位移。LazyColumn 只渲染当前可见窗口，整体向下平移会露出顶部未渲染区域，形成大块空白。正确做法是先抵消尚未结算的向上视觉位移，再把已经结算进真实滚动的补偿尽快用真实滚动回退。
- 键盘开始关闭时，如果没有表情面板或更多面板接管底部空间，底部遮挡高度应立即归零。底部栏和消息列表要瞬间回到关闭后的布局位置，不能跟随系统 IME 逐帧下降动画缓慢下移。
- 从键盘切换到表情面板、快捷回复或更多面板时，必须先发布目标面板高度，再隐藏键盘或清除输入框焦点。工具栏按钮的按下阶段不能抢先触发“键盘关闭归零”，否则底部栏会先落到底部再升到目标面板高度。
- 如果当帧没有完整移动到位，剩余距离仍属于同一次遮挡变化，后续继续补齐；遮挡减少时，先取消未完成的上移，再按减少的遮盖量下移。
- 实现上需要记录上一次已生效的底部遮挡高度，以及尚未完成的补偿位移。新的遮挡变化到来时，先结算未完成位移，再按新旧遮挡高度差计算本次应移动的距离。
- 已经有尚未完成的遮挡补偿位移时，不能再次把同一个遮挡高度当成“未应用遮挡”重复入账；应先消费已有 pending 位移，避免同一次键盘升起被补偿多次。
- 底部栏被键盘或面板抬起时，底部栏下方需要有同色背景填充，避免键盘或面板动画过程中短暂露出底部栏下面的消息内容。

约束：

- 这条路径只处理“底部遮挡高度变化导致的相对位移”，不是“滚到底部”。
- 不因为最后一条信息是否可见、当前内容是否接近底部或用户是否正在触摸列表而滚到底部；用户触摸也不会暂停或取消遮挡补偿。
- 键盘、底部栏和消息列表的运动应在同一次状态变化里完成。升起同步依赖当帧向上视觉位移；收起同步依赖取消未结算视觉位移和真实滚动回退，不能用向下视觉平移制造顶部空白。
- 遮挡变化必须在主遮挡补偿路径里一次入账、一次消费；不能额外新增事后兜底滚动，也不能产生无法在键盘关闭时回退的额外 scroll delta。

关键边界场景：

1. 用户先轻微下滑消息列表，让最后一条可见消息的底部已经被底部栏裁掉一部分。
2. 用户点击输入栏，键盘弹起，底部栏上移到键盘上方。
3. 消息列表只应上移“键盘新遮住了原本可见内容”的高度。键盘弹起前已经藏在底部栏下面的消息内容不应被当成新遮挡内容，也不应被借机完整露出。
4. 键盘弹起完成后，最后一条被遮挡的消息可以贴近输入栏上沿，但它和输入栏之间的呼吸间距应与键盘弹起前基本一致，不应明显变窄，也不应出现明显大空白。
5. 键盘关闭开始时，底部栏和列表应在同一次状态变化中瞬间回退到弹起前的阅读语境，不跟随键盘下降动画，也不留下额外底部空白。
6. 键盘已经展开时，用户点击表情、快捷回复或更多按钮，工具栏的 pointer down 阶段不应被当作输入栏外部点击，也不能先隐藏键盘。
7. 工具栏按钮 click 阶段应先发布目标面板高度，再清除输入框焦点和隐藏键盘。
8. 键盘切换到底部面板时，底部栏和消息列表只运动“键盘高度与目标面板高度的差值”；不能先回到底部，再从底部升到目标面板高度。
9. 如果用户关闭面板且没有新的键盘或其他面板接管，底部遮挡才可以归零，并触发一次完整回退。
10. 快速连续点击输入框或系统返回键导致键盘升起、落下、再次升起时，底部栏和消息列表必须使用同一帧的遮挡高度；不能出现底部栏已经正确运动但消息内容停在原位的状态。
11. 快速切换过程中，如果上一轮视觉上移还没来得及结算成真实滚动，新一轮遮挡减少应先抵消未结算的上移，再回退已经结算的真实滚动；不能因为 pending 未消费完而多退或少退，也不能用整条列表向下平移来伪装回退。
12. 用户先点输入框升起键盘，再点表情或快捷回复切到底部面板，最后再点输入框切回键盘时，消息列表必须补“键盘高度 - 面板高度”的正向差值。例如日志里表情面板高度 669px、键盘遮挡 820px，切回键盘时应产生 `delta=151`、`rise=151`，并在下一帧真实滚动消费 151px；不能出现 `delta=151` 但 `rise=0`。
13. 快捷回复、更多面板与键盘高度不同，也走同一条差值规则。例如快捷回复面板 735px、键盘遮挡 820px，切回键盘时应补 85px。
14. 这类面板到键盘的差值补偿不能通过事后 `scrollToBottom()` 兜底。它仍是相对遮挡补偿，必须可对称回退，并且不改变用户是否在看最新消息的判断。

实现复盘：

- 本次问题的日志形态是：表情面板切回键盘时已经算出 `prev=669`、`scrollObs=820`、`delta=151`，但 `rise=0`，后续没有 `settleRise` 消费，因此消息仍停在面板高度对应的位置，被更高的键盘遮住。
- 根因是补偿函数在已经有 `engagedBottomCompensationPx` 的情况下，仍先执行“当前可见内容是否被遮挡”的初次升起判断；由于当前消息已经被面板裁剪过，这个判断会把新增的键盘高度差过滤掉。
- 修复后的判定顺序是：如果 `activeBottomCompensationPx > 0` 且本帧 `rawDeltaPx > 0`，直接返回 `rawDeltaPx`；只有 `activeBottomCompensationPx == 0` 的第一次升起才调用当前可见内容遮挡判断。
- 验证日志应看到：表情面板切键盘 `delta=151 rise=151`，随后 `settleRise requested=151 consumed=151 actual=151`；快捷回复切键盘同理 `delta=85 rise=85`，随后消费 85px。

与游戏/锁分模式的关系：

- 本文定义的是普通对话模式，但当前 Android 实现里，有消息后的 `galgame` 和 `galgame_lock` 仍复用同一个 `ChatInputBar`、同一个 `LazyColumn` 和同一套底部遮挡补偿账本。因此这次“已处于遮挡补偿状态时直接补正向差值”的规则必须保持在共享补偿路径里，不能只在普通模式分支里处理。
- `galgame` / `galgame_lock` 的空消息开始界面是独立的 `verticalScroll + imePadding` 容器，且不显示聊天输入栏，不涉及这套消息列表遮挡补偿。
- 当前检查结论：有消息后的锁分模式不需要新增第二套修复；它已经通过共享补偿路径获得同样的面板/键盘差值补偿。后续如果锁分模式拆出独立列表或独立输入栏，必须同步迁移这条规则。

### 6. 语音转写展开

当语音消息的转写展开后，如果转写底部会被输入栏或键盘遮住，会局部滚动一点距离，让转写内容露出来。

约束：

- 用户正在触摸列表时跳过。
- 用户打开转写时会抑制普通自动跟随。抑制范围只覆盖本次转写展开和局部露出过程；展开处理结束后，后续新消息仍按普通自动跟随规则重新判断。
- 抑制需要有兜底释放窗口，避免转写布局没有触发局部滚动回调时，普通自动跟随永久保持关闭。当前实现使用短保护窗口释放；如果期间用户正在触摸列表，则仍以用户触摸状态优先。

### 7. 加载更多历史后的视角保持

用户滚到顶部附近加载更早历史时，会记录当前首个可见消息作为视角锚点。历史消息插入列表头部后，会回到这个锚点位置，避免加载历史后视角跳动。

这不是滚到底部，而是保持用户正在查看的历史位置。

### 8. 点击引用消息跳转

用户点击引用卡片时，会跳转到被引用消息所在位置。

这属于用户主动导航，不属于自动跟随。

### 9. 消息列表和关系页面切换

用户在消息列表和关系页面之间左右滑动时，底部栏也会跟着移动。这个过程会改变消息列表底部的可视空间，因此需要纳入底部遮挡补偿。

规则：

- 从消息列表切到关系页面时，如果底部栏向下离开消息列表区域，消息列表也应按底部栏实际移动距离同步下移。
- 从关系页面切回消息列表时，如果底部栏向上回到消息列表区域，消息列表也应按底部栏实际移动距离同步上移。
- 这条路径只处理“页面切换导致的底部栏相对位移”，不是“滚到底部”。
- 不应因为最后一条信息是否可见、当前是否接近底部、是否有新消息，而额外触发自动滚动。
- 如果切换过程中底部栏只移动了一部分，消息列表也只补偿这一部分；切换取消或反向滑回时，已经应用的补偿必须对称回退。
- 底部栏可见高度、消息列表相对滚动量和消息列表可视区域必须共用同一个页面进度和同一个输入栏静止高度，在同一次布局帧内完成运动。
- 关系页切换不能通过给消息页外层容器加顶部 padding、offset 或裁剪来伪装消息运动。这样只会把当前已显示的消息截断；如果列表上方还有历史消息，应该通过 `LazyListState` 向上取更多 item 显示出来。
- 切换完成后不能再用 `scrollToItem`、锚点还原或额外相对滚动补偿尾差。用户松手后不应看到消息列表再次“补一下”。
- 如果切换取消或反向滑回，只按当前页面进度自然回退；不需要记录、恢复或比较消息锚点。

效果要求：

- 消息列表和底部栏应像绑定在一起移动，不能出现底部栏已经归位但消息列表没有跟上的情况。
- 切换完成后，用户看到的消息位置应与切换前保持同一阅读语境，只扣除或恢复底部栏占用的空间。

## 回前台行为

当前回到前台时只做这些事情：

- 设置当前会话为活跃会话。
- 同步服务端连接的活跃会话状态。
- 标记当前角色和当前模式已读。
- 做轻量恢复与补拉。

当前不再做：

- 不记录离开前是否在底部。
- 不因为回前台本身滚到底部。
- 不因为回前台本身改变消息列表位置。
- 回前台补拉到新消息时，不只因为“有新消息”就改变用户离开时的阅读位置；是否跟随仍以补拉前最后一条信息是否可见为准。
- 会记录离开前最后一条消息是否可见，用来处理“消息在后台已经到达，回前台时数据已经更新”的场景。这不是回前台无条件滚动，而是离开前可见性快照的延续。

## 后续优化方向

这些优化不改变界面，只减少无意义的列表替换、二次布局和可见滚动。

1. 缓存命中后优先增量补拉。

   当前缓存展示后仍会进入服务端刷新。更理想的策略是：如果缓存里有会话标识和最大消息序号，优先只拉取比当前消息更新的内容。没有新消息时，只结束后台刷新，不替换当前列表。只有缺少消息序号、会话不确定或增量请求失败时，才回退到最新 50 条分页。

2. 明确区分“最新页”和“历史懒加载”。

   普通模式进入聊天页时只展示最新窗口，用户向上滚动时才加载更早历史。自动滚动逻辑只应把初始展示视为“最新页定位到底部”，不应把它理解成完整历史加载完成。

3. 服务端刷新后做更严格的可见内容等价判断。

   如果服务端返回的数据和当前界面在可见内容层面一致，应保留当前列表，不触发消息列表重新布局。等价判断应覆盖消息身份、发送方、内容、时间、展示内容、引用、附件、语音状态、说话角色等会影响界面的字段。

4. 初始滚动只绑定首次展示窗口。

   初始展示滚动只用于遮罩还没揭开时的首次定位。服务端刷新完成后，如果没有新增消息，不应重新定位到底部；刷新本身不等于新消息。遮罩状态不能因为 `conversationId` 落定而重建，否则用户会看到重复加载和重复定位。

5. 不优先缩小 50 条初始窗口。

   消息列表只渲染可见区域附近的内容，50 条作为初始窗口可以保留。优先优化无意义状态替换、后台刷新覆盖和二次布局，而不是先减少分页数量。

## 已确认的设计取舍

1. 最后一条信息是否可见的判断语义偏宽：它只要求最后一条信息部分可见，所以“最后一条还露一点”会被视为最后一条信息可见。这个边界情况可以接受。
2. 后台刷新、回前台补拉和服务端同步以刷新前的最后一条信息是否可见为准。刷新前看得到最后一条信息则继续跟随，刷新前看不到最后一条信息则保持用户阅读位置。

## 硬性要求

1. 键盘、底部栏和底部面板造成的遮挡补偿必须按遮盖变化量严格对称：多遮盖多少就上移多少，少遮盖多少就下移多少；面板高度切换时也按遮盖变化量补偿。
2. 底部遮挡补偿必须无视用户触摸状态；这条路径不是自动跟随，不受用户触摸或最后一条信息是否可见影响。
3. 遮挡升起时列表位移必须在主遮挡补偿路径里一次完成；不能把“输入栏已动、列表未动”的中间态留给事后兜底。
4. 不应新增任何事后兜底式滚动路径；新增场景必须纳入明确的触发条件、位移计算和对称回退规则。
5. 初次计算键盘或底部栏升起造成的遮挡时，内容底部必须被限制在遮挡变化前的可见边界内；遮挡变化前已经被旧底部栏裁掉的内容不参与新遮挡量计算。
6. 当同一次遮挡变化还有 pending 位移没有消费完时，不能再次把相同遮挡高度作为“未应用遮挡”重复加入 pending 账本。
7. 表情面板、更多面板和键盘一样属于底部遮挡源；它们通过布局而不是 graphicsLayer 产生的上移，也必须进入遮挡顶部计算。
8. 键盘关闭目标已经是 0 时，普通聊天界面不能继续使用 IME onProgress 的递减高度驱动底部栏和消息列表；应把本次遮挡减少折算成一次完整回退。
9. 键盘切换到底部面板时，目标面板高度必须在清焦点和隐藏键盘之前进入遮挡计算；这类交接只按键盘高度与面板高度的差值运动，不能经过 0 高度中间态。
10. 键盘 IME 高度必须在同一布局帧内同时驱动输入栏位移和消息列表遮挡补偿；不能让输入栏直接读取更新更快的 graphics/draw 阶段高度，而列表仍使用旧 composition 高度。
11. 消息列表升起避让帧必须先使用向上 `graphicsLayer` 视觉位移和底部栏同帧移动，再在下一帧以后把 pending 位移结算进真实滚动；结算动作不能成为用户可见的追赶动画。遮挡减少时不能使用向下 `graphicsLayer` 平移整条列表，应直接取消未结算上移并真实回退已结算补偿。
12. 快速键盘切换只能走同一条主遮挡补偿路径；不能额外触发滚到底部，也不能绕过对称回退。
13. 后台刷新等价判断不能只比较消息数量、首尾 key 或末条角色；必须比较可见消息中会影响布局和阅读语义的字段。等价刷新不能触发滚动。
14. 初始加载遮罩的 key 不能包含会在同一页面生命周期内从空值落定的 `conversationId`；角色和模式不变时，遮罩和初始定位只能发生一次。
15. 回前台自动跟随只能消费 `ON_PAUSE` 时记录的最后一条可见性快照；不能在没有快照、快照不可见、角色/模式不匹配、或消息尾部未变化时滚动。

## 伪代码

下面的伪代码只描述普通对话模式。剧情模式和锁分剧情模式如果有独立滚动策略，不应复用这里的入口。

约定：

- `scrollBy(+dy)` 表示列表内容上移，视觉上用户看到更靠后的消息。
- `scrollBy(-dy)` 表示列表内容下移，视觉上用户看到更靠前的消息。
- `scrollToBottom()` 是明确滚到底部，只能在初始定位、用户发送、允许自动跟随这几类入口里调用。
- `onBottomObstructionChanged()` 是相对遮挡补偿入口，不能在内部调用 `scrollToBottom()`。
- `applyRelativeScroll()` 只做相对位移，不能改变“是否应该跟随到底部”的判断。

```kotlin
// 普通对话模式的滚动控制器。
// 这里把“是否滚到底部”和“是否做相对位移补偿”拆开维护，
// 避免键盘、底部栏、刷新、回前台等事件互相借用滚动入口。
class NormalChatScrollController {

    // 当前消息列表是否正在被用户手指直接操作。
    // 这个状态只用于阻止自动跟随和局部露出类滚动，
    // 不能用于阻止底部遮挡补偿，因为遮挡补偿是布局同步的一部分。
    var isUserTouchingList: Boolean = false

    // 初始加载遮罩是否还存在。
    // 初始滚到底部只允许发生在遮罩揭开前，
    // 避免普通对话过程中因为 loading 状态变化反复回到底部。
    var isInitialMaskVisible: Boolean = true

    // 语音转写展开、引用跳转等用户主动导航期间，可以短暂抑制普通自动跟随。
    // 抑制只覆盖当前主动导航动作，不表示用户永久离开底部。
    var suppressAutoFollow: Boolean = false

    // 上一次已经生效的底部遮挡高度。
    // 例如输入栏高度、键盘高度、扩展面板高度、关系页切换时底部栏占用高度等，
    // 都应该被折算成“消息列表底部当前被遮住多少像素”。
    var appliedBottomObstructionPx: Int = 0

    // 尚未完成的遮挡补偿位移。
    // 如果某一帧 RecyclerView 因为边界、布局未完成或动画合并没有完整移动，
    // 剩余距离必须继续记在这里，后续帧补齐，不能转成 scrollToBottom。
    var pendingObstructionCompensationPx: Int = 0

    // 助手消息自动跟随的防抖任务。
    // 多条助手消息短时间连续到达时，只保留最后一个任务，
    // 等内容稳定后滚一次，减少可见跳动。
    var assistantFollowJob: Job? = null

    // 刷新或补拉开始前的快照。
    // 注意这里记录的是“刷新前最后一条是否可见”，不是刷新结束后的状态。
    var refreshSnapshot: RefreshSnapshot? = null

    // App 退到后台前的快照。
    // 这笔快照只服务于“消息在后台已经到达，回前台时数据已经更新”的场景。
    // 它不能被用作回前台无条件滚动。
    var foregroundResumeSnapshot: ForegroundResumeSnapshot? = null

    data class RefreshSnapshot(
        val wasLastMessageVisibleBeforeRefresh: Boolean,
        val visibleAnchor: VisibleAnchor?,
        val visibleMessagesBeforeRefresh: List<Message>
    )

    data class ForegroundResumeSnapshot(
        val characterId: String,
        val mode: String,
        val conversationId: String?,
        val messageCount: Int,
        val lastMessageKey: String?,
        val wasLastMessageVisibleOnPause: Boolean,
        val resumeRequestedAtMs: Long = 0
    )

    data class VisibleAnchor(
        val messageId: String,
        val offsetFromListTopPx: Int
    )

    fun onInitialMessagesPresented() {
        // 进入聊天页后，本地缓存或服务端最新窗口已经完成首次显示。
        // 只要初始遮罩还在，就直接定位到底部；
        // 用户看不到这个滚动过程，因此不会产生明显跳动。
        if (isInitialMaskVisible) {
            scrollToBottom(reason = "initial_latest_window")
        }
    }

    fun onInitialMaskDismissed() {
        // 遮罩揭开后，初始定位通道永久关闭。
        // 后续即使 loading 状态重新变化，也不能再走初始滚到底部。
        isInitialMaskVisible = false
    }

    fun onUserMessageAppended(appendedMessage: Message) {
        // 用户发送消息是主动行为，可以把视角带回当前对话尾部。
        // 这里不需要检查发送前用户是否正在看历史，
        // 因为发送动作本身已经表达了继续当前对话的意图。
        if (appendedMessage.isFromCurrentUser && isLastMessage(appendedMessage)) {
            scrollToBottom(reason = "user_message_appended")
        }

        // 键盘或底部栏因为发送动作产生的遮挡变化，不在这里处理。
        // 它们会通过 onBottomObstructionChanged() 走相对补偿路径。
    }

    fun beforeAssistantMessagesAppend(): Boolean {
        // 助手消息入列前先取快照。
        // 自动跟随是否允许，只看旧列表最后一条是否可见；
        // 不要等新消息插入后再判断，否则新消息本身会改变可见性结论。
        return isLastMessageVisible()
    }

    fun afterAssistantMessagesAppend(wasLastMessageVisibleBeforeAppend: Boolean) {
        // 用户打开语音转写、点击引用跳转等主动导航期间，
        // 本轮普通自动跟随直接放弃，不在动作结束后补滚。
        if (suppressAutoFollow) return

        // 如果新消息到达前最后一条已经不可见，说明用户在看历史。
        // 这时新增助手消息不能把用户拉回底部。
        if (!wasLastMessageVisibleBeforeAppend) return

        // 防抖前取消上一轮等待。
        // 这样 200ms 内连续到达的助手消息只会触发一次最终滚动。
        assistantFollowJob?.cancel()
        assistantFollowJob = launchAfter(200.milliseconds) {
            // 防抖真正执行时再次看用户是否正在触摸列表。
            // 如果正在触摸，跳过本轮自动跟随；
            // 不要在用户松手后额外补一次，否则会变成事后兜底滚动。
            if (isUserTouchingList) return@launchAfter

            scrollToBottom(reason = "assistant_messages_debounced")
        }
    }

    fun onServerRefreshStart() {
        // 后台刷新、回前台补拉、服务端同步开始前统一取快照。
        // 后续是否跟随，只认这个时间点的最后一条可见性。
        refreshSnapshot = RefreshSnapshot(
            wasLastMessageVisibleBeforeRefresh = isLastMessageVisible(),
            visibleAnchor = captureFirstVisibleMessageAnchor(),
            visibleMessagesBeforeRefresh = currentVisibleRelevantMessages()
        )
    }

    fun onServerRefreshFinished(diff: MessageListDiff) {
        val snapshot = refreshSnapshot
        refreshSnapshot = null

        if (snapshot == null) {
            // 没有快照时不要猜测用户意图。
            // 保守做法是保持当前位置，等待下一次明确入口。
            return
        }

        if (isSameVisibleMessageList(
                before = snapshot.visibleMessagesBeforeRefresh,
                after = currentVisibleRelevantMessages()
            )
        ) {
            // 后台刷新可能替换了服务器元数据，但当前可见消息在布局和阅读语义上等价。
            // 这种变化不能触发滚动，也不能重建初始遮罩。
            return
        }

        if (!diff.affectsVisibleLayout && !diff.hasNewerMessages && !diff.hasBackfilledMessages) {
            // 服务端返回内容和当前可见界面等价，
            // 例如只更新了后台元数据或不会影响布局的状态字段。
            // 这时不替换视角，也不滚到底部。
            return
        }

        if (snapshot.wasLastMessageVisibleBeforeRefresh) {
            // 刷新前用户仍在最新位置，
            // 刷新后如果出现新消息、补齐消息或影响布局的数据替换，
            // 可以继续跟随到底部。
            if (!isUserTouchingList) {
                scrollToBottom(reason = "refresh_follow_latest")
            } else {
                // 刷新完成瞬间如果用户正在拖动列表，就不抢手势。
                // 此时恢复刷新前锚点，避免数据替换导致当前阅读内容跳动。
                restoreVisibleAnchor(snapshot.visibleAnchor)
            }
            return
        }

        // 刷新前用户看不到最后一条，说明用户正在读历史。
        // 即使刷新带来新消息，也优先恢复刷新前的阅读锚点。
        restoreVisibleAnchor(snapshot.visibleAnchor)
    }

    fun onAppPause(characterId: String, mode: String, conversationId: String?) {
        // 离开聊天页或 App 退后台前，记录当前尾部可见性。
        // 如果这时最后一条不可见，回前台后即使有通知和新消息，也应尊重用户正在看历史。
        foregroundResumeSnapshot = ForegroundResumeSnapshot(
            characterId = characterId,
            mode = mode,
            conversationId = conversationId,
            messageCount = currentMessages().size,
            lastMessageKey = currentMessages().lastOrNull()?.stableKey,
            wasLastMessageVisibleOnPause = isLastMessageVisible()
        )
    }

    fun onAppResume(characterId: String, mode: String, conversationId: String?) {
        val snapshot = foregroundResumeSnapshot ?: return
        if (!snapshot.wasLastMessageVisibleOnPause) return
        if (snapshot.characterId != characterId || snapshot.mode != mode) {
            foregroundResumeSnapshot = null
            return
        }
        if (
            snapshot.conversationId != null &&
            conversationId != null &&
            snapshot.conversationId != conversationId
        ) {
            foregroundResumeSnapshot = null
            return
        }

        // 只挂起一次请求；真正消费要等刷新、补拉和遮罩稳定。
        foregroundResumeSnapshot = snapshot.copy(resumeRequestedAtMs = nowMs())
    }

    fun onForegroundResumeSettled() {
        val snapshot = foregroundResumeSnapshot ?: return
        if (snapshot.resumeRequestedAtMs <= 0) return
        if (isInitialMaskVisible || isLoadingHistory() || isBackgroundRefreshing()) return

        val currentLastKey = currentMessages().lastOrNull()?.stableKey
        val tailChanged =
            currentMessages().size > snapshot.messageCount ||
                (currentMessages().size == snapshot.messageCount && currentLastKey != snapshot.lastMessageKey)

        if (!tailChanged) {
            if (nowMs() - snapshot.resumeRequestedAtMs > 3500) {
                // 没有后台新消息落地，丢弃请求，避免影响之后前台期间的新消息。
                foregroundResumeSnapshot = null
            }
            return
        }

        if (isUserTouchingList) return

        foregroundResumeSnapshot = null
        suppressAutoFollow = false
        scrollToBottom(reason = "foreground_resume_new_message")
    }

    fun normalizeBottomObstructionPx(
        rawBottomObstructionPx: Int,
        keyboardTargetBottomPx: Int,
        panelLiftPx: Int
    ): Int {
        // 键盘关闭的目标高度已经是 0 时，聊天界面不跟随系统 IME 下降动画。
        // 这时虽然 onProgress 还会继续给出逐帧递减的当前键盘高度，
        // 但普通对话的底部栏应该已经回到底部，消息列表也应该同步回退。
        // 如果表情面板或更多面板正在接管底部空间，则仍保留面板遮挡高度。
        if (keyboardTargetBottomPx == 0 && panelLiftPx == 0) {
            return 0
        }

        // 非键盘关闭场景继续使用真实遮挡高度：
        // 键盘弹起、表情面板展开、更多面板展开、键盘和面板交接都走同一套补偿。
        return rawBottomObstructionPx.coerceAtLeast(0)
    }

    fun sampleBottomObstructionForLayoutFrame(): Int {
        // 输入栏 graphics 位移、列表 bottom padding、遮挡顶部和补偿账本
        // 必须共用这个布局帧采样值。
        // 不允许输入栏在 graphics/draw 阶段直接读取更新更快的 IME 高度，
        // 而列表仍停留在上一帧 composition 高度。
        val rawBottomObstructionPx = max(
            keyboardVisibleOrCachedLiftPx,
            activePanelHeightPx,
            keyboardToPanelHandoffLiftPx
        )
        return normalizeBottomObstructionPx(
            rawBottomObstructionPx = rawBottomObstructionPx,
            keyboardTargetBottomPx = keyboardTargetBottomPx,
            panelLiftPx = activePanelHeightPx
        )
    }

    fun onToolbarPanelButtonPressed(targetPanelHeightPx: Int) {
        // 工具栏按钮从键盘切到底部面板时，不能在 pointer down 阶段先隐藏键盘。
        // 正确顺序是先让目标面板高度进入状态，再隐藏键盘或清焦点。
        // 这样 onBottomObstructionChanged() 看到的是：
        //   old = 键盘高度
        //   new = 面板高度
        // 列表和底部栏只运动两者差值。
        if (targetPanelHeightPx > 0) {
            setActivePanelHeight(targetPanelHeightPx)
            hideKeyboardAndClearInputFocus()
            return
        }

        // 关闭当前面板时没有新的底部空间接管，可以直接归零。
        setActivePanelHeight(0)
        hideKeyboardAndClearInputFocus()
    }

    fun onInputBarPointerDown(windowPosition: Offset) {
        // 输入栏容器会在 pointer down 阶段判断是否点击了输入框外部。
        // 这个阶段只能处理真正的外部区域，不能把工具栏按钮区域当成外部点击。
        // 否则工具栏按钮的 click 还没来得及发布目标面板高度，
        // 键盘关闭归零就会先触发，造成底部栏先落到底部再升到面板高度。
        if (isInsideInputField(windowPosition) || isInsideSendButton(windowPosition)) {
            keepKeyboard()
            return
        }

        if (isInsideInputToolbar(windowPosition)) {
            // 工具栏按钮会在自己的 click 回调里决定是否切换面板。
            // pointer down 阶段只负责放行，不改变键盘或面板状态。
            keepKeyboardUntilToolbarClick()
            return
        }

        hideKeyboardAndClearInputFocus()
    }

    fun onBottomObstructionChanged(rawBottomObstructionPx: Int) {
        // 这是唯一处理键盘、底部栏、扩展面板遮挡变化的入口。
        // 注意：这里不能检查 isLastMessageVisible()，
        // 也不能因为用户正在触摸列表而跳过。

        val newBottomObstructionPx = normalizeBottomObstructionPx(
            rawBottomObstructionPx = rawBottomObstructionPx,
            keyboardTargetBottomPx = keyboardTargetBottomPx,
            panelLiftPx = panelLiftPx
        )
        val oldBottomObstructionPx = appliedBottomObstructionPx
        val rawDeltaPx = newBottomObstructionPx - oldBottomObstructionPx
        val activeCompensationPx =
            settledObstructionScrollPx +
            pendingVisualRisePx
        val hasPendingVisualCompensation =
            pendingVisualRisePx > 0 || pendingVisualRevertPx > 0

        // 先更新已生效遮挡高度。
        // 后续即使本帧没有完成真实滚动，升起时也会先用向上 visual 位移保持同帧同步。
        appliedBottomObstructionPx = newBottomObstructionPx

        if (rawDeltaPx == 0 && hasPendingVisualCompensation) {
            // 遮挡高度没有新变化，只是上一帧视觉位移还没结算进真实滚动。
            // 这里不能把同一个 newBottomObstructionPx 再入账一次，
            // 否则键盘升起过程中会出现重复上移，输入栏上方留下大空白。
            requestNextFrameToSettleVisualCompensation()
            return
        }

        if (rawDeltaPx > 0) {
            // 新增遮挡为正数：列表需要上移。
            // 已经处于遮挡补偿中时，后续高度变化按遮挡变化量继续跟随；
            // 第一次进入遮挡时，才根据当前可见内容限制实际需要上移的距离。
            val frameRisePx =
                if (activeCompensationPx > 0) {
                    rawDeltaPx
                } else {
                    computeActuallyCoveredVisibleContentPx(
                        newBottomObstructionPx = newBottomObstructionPx,
                        obstructionDeltaPx = rawDeltaPx
                    ).coerceAtMost(rawDeltaPx)
                }

            // 关键：当帧先发布视觉上移，让消息内容和底部栏使用同一个遮挡高度一起动。
            // 真实滚动不在这里立即执行，避免和当前布局帧竞争。
            pendingVisualRisePx += frameRisePx
            listVisualTranslationYPx = -pendingVisualRisePx
            requestNextFrameToSettleVisualCompensation()
            return
        }

        if (rawDeltaPx < 0) {
            // 遮挡减少为负数：列表需要下移。
            var remainingDropPx = -rawDeltaPx

            // 如果上一轮上移还只是视觉位移，先抵消未结算的上移；
            // 这可以处理“键盘刚升起又立刻关闭/切换面板”的快速场景。
            val cancelPendingRisePx = min(remainingDropPx, pendingVisualRisePx)
            pendingVisualRisePx -= cancelPendingRisePx
            remainingDropPx -= cancelPendingRisePx

            // 剩余需要下移的部分，说明已经结算进真实滚动了；
            // 不能用整条列表向下视觉平移，否则顶部会露出未渲染区域。
            // 这里只挂起真实回退请求，尽快用真实滚动消账。
            val frameRevertPx = min(remainingDropPx, settledObstructionScrollPx)
            pendingVisualRevertPx += frameRevertPx
            listVisualTranslationYPx = -pendingVisualRisePx
            requestNextFrameToSettleVisualCompensation()
        }
    }

    fun computeActuallyCoveredVisibleContentPx(
        newBottomObstructionPx: Int,
        obstructionDeltaPx: Int
    ): Int {
        // 当前帧里列表可见内容的最低点。
        // 这个值来自当前 layoutInfo，不能复用历史帧缓存。
        val currentVisibleContentBottomPx = currentLayoutVisibleContentBottomPx()

        // 新遮挡区域的顶部，也就是键盘或输入栏升起后消息最多能贴到的位置。
        // 这里要用键盘、表情面板、更多面板合并后的总遮挡高度，
        // 不能只取键盘 graphics 位移。
        val newObstructionTopPx = listViewportBottomPx - newBottomObstructionPx

        // 遮挡变化前的可见边界。
        // 例如键盘升起前，底部栏已经盖住了一部分消息，
        // 那部分消息虽然属于当前布局项，但用户实际上看不到，
        // 所以不能把它算成“被键盘新遮住的内容”。
        val previousVisibleBottomPx = newObstructionTopPx + obstructionDeltaPx

        // 只允许当前可见内容参与计算。
        // 如果内容底部超过旧可见边界，就裁到旧可见边界；
        // 这样用户先把消息拖到被底部栏挡住，再点输入栏时，
        // 列表只会上移已露出部分需要避让的高度。
        val cappedVisibleContentBottomPx = min(
            currentVisibleContentBottomPx,
            previousVisibleBottomPx
        )

        val preChangeBreathingGapPx =
            (previousVisibleBottomPx - cappedVisibleContentBottomPx).coerceAtLeast(0)
        val preservedBreathingGapPx =
            if (preChangeBreathingGapPx <= maxPreservedBottomBreathingGapPx) {
                max(naturalBottomGapPx, preChangeBreathingGapPx)
            } else {
                // 内容离底部栏很远时，不保留这个大间距；
                // 否则用户看历史消息时也会被额外上推。
                naturalBottomGapPx
            }

        val desiredContentBottomPx = cappedVisibleContentBottomPx + preservedBreathingGapPx
        return (desiredContentBottomPx - newObstructionTopPx).coerceAtLeast(0)
    }

    fun onNextFrameToSettleVisualCompensation() {
        // 向上视觉位移已经在上一帧和底部栏同帧展示。
        // 现在把 pending 位移结算进真实列表滚动，并同步扣减 visual 位移。
        // 回退请求不做向下视觉位移，直接用真实滚动消账，避免顶部空白。

        if (pendingVisualRevertPx > 0) {
            val consumedPx = applyRelativeScroll(-pendingVisualRevertPx)
            val actualRevertPx = abs(consumedPx)
            pendingVisualRevertPx -= actualRevertPx
            settledObstructionScrollPx -= actualRevertPx
        }

        if (pendingVisualRisePx > 0) {
            val consumedPx = applyRelativeScroll(+pendingVisualRisePx)
            pendingVisualRisePx -= consumedPx
            settledObstructionScrollPx += consumedPx
        }

        listVisualTranslationYPx = -pendingVisualRisePx

        if (pendingVisualRisePx != 0 || pendingVisualRevertPx != 0) {
            // 当前布局帧无法完整消费时继续挂账；仍然不能转成 scrollToBottom。
            requestNextFrameToSettleVisualCompensation()
        }
    }

    fun onVoiceTranscriptExpand(transcriptBottomPx: Int, visibleBottomPx: Int) {
        // 语音转写展开是用户主动操作。
        // 展开期间先抑制普通自动跟随，避免助手消息防抖滚动抢走视角。
        suppressAutoFollow = true

        try {
            if (isUserTouchingList) {
                // 用户正在触摸列表时，不做局部露出滚动。
                // 这条规则只影响转写展开，不影响底部遮挡补偿。
                return
            }

            val coveredPx = transcriptBottomPx - visibleBottomPx
            if (coveredPx > 0) {
                // 这里只滚动刚好露出转写所需的一小段距离。
                // 它不是普通自动跟随，也不是滚到底部。
                applyRelativeScroll(coveredPx)
            }
        } finally {
            // 转写展开和局部露出处理结束后解除抑制。
            // 后续新消息继续按“新增前最后一条是否可见”重新判断。
            suppressAutoFollow = false
        }
    }

    fun onLoadOlderMessagesStart(): VisibleAnchor? {
        // 历史懒加载前记录第一个可见消息。
        // 插入更早消息后用它恢复视角，
        // 避免列表头部插入内容导致当前阅读位置跳动。
        return captureFirstVisibleMessageAnchor()
    }

    fun onLoadOlderMessagesFinished(anchor: VisibleAnchor?) {
        // 历史加载完成后恢复锚点。
        // 这不是滚到底部，也不受最后一条是否可见影响。
        restoreVisibleAnchor(anchor)
    }

    fun onQuoteMessageClicked(targetMessageId: String) {
        // 点击引用属于用户主动导航。
        // 它可以跳到任意历史位置，并且不应触发自动跟随。
        suppressAutoFollow = true
        try {
            scrollToMessage(targetMessageId)
        } finally {
            suppressAutoFollow = false
        }
    }

    fun onRelationPageProgressChanged(pageProgress: Float, restingInputHeightPx: Int) {
        // pageProgress: 0 表示完全在消息页，1 表示完全在关系页。
        // 关系页切换不是滚动场景，也不是底部遮挡兜底；
        // 它只是一组由同一个页面进度驱动的布局尺寸。
        val progress = pageProgress.coerceIn(0f, 1f)

        // 底部栏可见高度和消息列表相对滚动量必须使用同一个静止高度。
        // 如果两边分别读取测量结果，就可能产生一帧差，
        // 用户会看到底部栏已经到位、消息列表最后又补一下。
        val visibleInputHeightPx = (restingInputHeightPx * (1f - progress)).roundToInt()
        val hiddenInputHeightPx = restingInputHeightPx - visibleInputHeightPx
        val hiddenHeightDeltaPx = hiddenInputHeightPx - previousHiddenInputHeightPx

        // 底部栏自身按 visibleInputHeightPx 裁切/布局。
        inputBar.layoutHeightPx = visibleInputHeightPx

        // 消息列表按隐藏高度的增量做固定相对滚动。
        // 不能用外层 top padding 或 offset 裁剪当前画面；
        // 如果上方还有历史消息，LazyList 应该继续组合并显示上方 item。
        val requestedOffset = firstVisibleItemScrollOffset - hiddenHeightDeltaPx
        val targetOffset = if (firstVisibleItemIndex == 0) {
            // 已经在第一条消息顶部时，没有更早消息可显示，不能请求负 offset 露出空白。
            requestedOffset.coerceAtLeast(0)
        } else {
            requestedOffset
        }
        messageList.requestScrollToItem(
            firstVisibleItemIndex,
            targetOffset,
        )
        previousHiddenInputHeightPx = hiddenInputHeightPx

        // 切换完成后不得再执行 scrollToItem 或额外 scrollBy。
        // 如果这里还需要尾部锚点恢复，说明两边没有共用同一帧高度源。
    }

    private fun scrollToBottom(reason: String) {
        // 唯一真正滚到底部的封装。
        // 新增滚动场景时，必须先确认它属于初始定位、用户发送或允许自动跟随，
        // 不能为了修复某个跳动问题在布局回调里临时调用这里。
        recyclerView.scrollToPosition(lastMessageIndex())
        logScroll(reason)
    }

    private fun applyRelativeScroll(deltaPx: Int): Int {
        // 相对位移封装。
        // deltaPx > 0：内容上移，用于底部遮挡增加或局部露出。
        // deltaPx < 0：内容下移，用于底部遮挡减少或切换回退。
        // 返回实际被 RecyclerView 消耗的像素，供 pending 记账。
        if (deltaPx == 0) return 0
        return recyclerView.scrollByAndReturnConsumed(deltaPx)
    }
```
