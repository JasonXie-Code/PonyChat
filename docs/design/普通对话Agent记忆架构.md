# 普通对话 Agent 与统一记忆架构

2026-09-06，新版 5.6.19。普通对话统一采用 DeepSeek Harness，模型为 deepseek-v4-flash-vision-exp，low 思考模式。本文描述本次实现；游戏与锁分模式保留各自独立的记忆机制。

## 角色与任务

一个角色身份，两个执行角色：前台聊天 Agent 即时回应、查阅往事和保存本轮明确事实；后台整理 Agent 在空闲、日期切换或用户请求时查漏、修订、整理摘要和关系认识。不会每轮固定调用两个 Agent，也不让多个 Agent 互相投票。旧历史不在升级时全量重算，角色再次产生消息或用户主动请求时才激活整理。用户明确请求的本日日摘优先于普通空闲任务。后台队列按用户和角色合并，持久化任务版本、租约与失败退避，服务重启后可恢复。

每轮聊天提供角色设定、近期原始聊天、最新用户消息、时间和必要环境。早期原文和长期记忆经工具按需读取。聊天 Agent 使用 read_history、search_memory、stage_memory、request_memory_review，以及图片识别、真实表情包检索与暂存工具。模型不能指定其他用户身份、直接操作数据库或执行设备命令。

后台使用同一 Harness，自主选择 read_history、search_memory、list_periods、read_period、read_summaries、stage_memory、stage_relationship_page。旧表只经 read_legacy 作为未核验线索，不能作为新的事实依据。旧普通对话的自动上下文摘要、空闲碎片提取、分层摘要和关系页面生成定时任务不再启动。旧客户端的 pipeline 设置也会进入新版 Agent。

关系页缺失或用户下拉刷新时，合并为一项高优先级整理请求。Agent 必须写齐关系概况、感受、双方画像、记住的小事、共同经历、下次话题和标签，才能结束这项请求；初次接触时允许明确表达尚待了解，不能编造经历。轮询不会反复提升版本而打断正在执行的任务。App 等待 queued/running 状态完成，空结果不作为稳定缓存；关系阶段不再根据消息数量自动推算。

游戏和锁分仍有独立存档及规则。本次将其分步生成与游戏记忆摘要的模型调用接到同一 Harness runtime，每个阶段是受限的独立运行，统一 deepseek-v4-flash-vision-exp、low。阶段顺序、原有提示、解析、校验、重试、体征结算、锁分、SSE 事件和存档保持既有行为；这是等效执行迁移，不把游戏记忆并入普通对话库。模型只能返回阶段结果，不能直接修改存档；用量仍归属原计费用户。

## 同一个记忆库

SQLite 的 agent_memory_heads 是当前版本指针，agent_memory_versions 保留所有版本，agent_memory_state 隔离用户、角色、重置世代和后台任务版本。原始聊天保持独立，不被摘要替换或裁剪。原文消息、用户手动编辑记录、已验证的下层记忆均带可复核来源。

| 属性 | 含义 |
| --- | --- |
| category | fact、preference、episode、activity、commitment、relationship、understanding、current_scene；daily、weekly、monthly、annual；关系页面 relationship_page |
| certainty | explicit 明确表达；observed 原文发生；inferred 可修订推测。长期认识不能伪装成用户明确偏好 |
| status | active、planned、completed、cancelled、retracted；计划与完成分开，取消约定更新原条目 |
| 来源 | 原消息 ID 和内容指纹；摘要还记录整个周期原文指纹 |
| 时间与版本 | 来源时间及未知时间说明、创建时间、entry_id、expected_version、version |
| 作用域 | 长期事实在同用户同角色间共享；current_scene 绑定原会话 |

聊天 Agent 的写入先暂存，回复成功保存且生成仍有效后原子提交。后台整理同样校验任务版本、角色重置世代和所有来源；聊天期间出现新信息时旧整理不能覆盖新状态。相同内容的事实去重，语义合并由 Agent 读取旧条目后更新版本完成。

修改、隐藏或删除来源后，相关记忆及其上层摘要立即退出有效检索，后台按现有可见原文重建。用户重置会提升世代并取消旧租约，旧任务即便晚返回也不能写回。隐藏的原文不能从旧记忆线索复活。

## 日摘、周月年摘要与关系页面

日摘主要依据当天完整可见原文，分页必须读完才允许保存。周/月可读覆盖范围完整的日摘；年可读完整月摘。缺失下层摘要时先补齐或直接回查整个周期原文。一个周期保留一个稳定条目并持续修订，禁止只读第一页便声称覆盖全天。

自动周期使用 Asia/Shanghai 的已结束日期；用户主动整理支持本日可更新日摘。每次整理预算有限，未覆盖的周期保持待处理并继续下一次任务。事实、事件、约定及角色认识由 Agent 判断，程序负责权限、覆盖、版本、来源有效性、交付与持久化约束。

关系页面的文字与条目由整理 Agent 保存为有来源的 relationship_page，再投影到既有页面结构；失效材料不再展示。用户手动设置关系阶段也写入统一库。长期记忆页面沿用稳定整数 ID 与四类/五层界面投影，保留手动新增、编辑、删除和重要度。

## 回复协议与终端形态

回复仍为 bubbles/parts，speech 与 action 分开。后端为动作添加中文括号，移除每段末尾的中文句号；自然正文禁止 Markdown。用户指定 1–5 段时必须精确生成相应文字气泡；明确要求的图片是额外图片消息，不占文字段数。辅助表达遵守《普通对话辅助表达规则》，不固定每轮加 emoji。

手机版是用户在自己手机下载安装的版本，主机版是自研设备搭载的版本。它们是同一个 App，根据安装环境自动选择运行形态。手机版从用户的聊天界面进入；主机版提供设备首屏。普通打开手机版不会自动出现 Companion 悬浮窗，两种形态共享同一套聊天与记忆后端。

## 验证要求

先用隔离 SQLite 验证跨用户隔离、来源失效、并发版本、重置中断、分页覆盖、重复写入与任务恢复，再运行真实 Harness 合成用例。生产验收只重置授权的 System/紫悦，服务器保留重置前 SQLite 快照并比对其他角色数据指纹。最后使用真实模拟器 UI 发送消息，核对实际服务器消息、素材附件和记忆记录，不能把合成素材选择当成真实图片交付。
