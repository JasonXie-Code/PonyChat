# 普通对话联网搜索与日历摘要上下文

2026-09-06。普通对话 Harness Agent 注册 `web_search`，唯一服务提供者是 Server-USA 的私有 SearXNG。现有记忆搜索、原文读取和表情包搜索仍是各自独立的本地工具。

## 联网搜索

- 服务：`ponychat-searxng.service`，目录 `/opt/ponychat-searxng`，仅监听 `127.0.0.1:18786`，独立 Python 环境与系统用户，开机自启。
- SearXNG 固定源码提交：`c7f3080aac5de13b619c4a5ab36590a2c5165e1c`。
- 配置上游为 Google、Google CSE、Yahoo、360search、Wikipedia。扩容前对11个候选进行42次单引擎查询，其中入选通道30次查询未见限流/验证码；这不是长期不限流承诺。Google/CSE属于同一供应商的两个通道。360权重0.4，CSE权重0.8，其余保持默认。
- Brave因先前多次限流移除；DuckDuckGo、百度、Qwant、Startpage出现验证码，搜狗解析错误，Seznam一次超时，Mojeek目标查询无结果，Bing此前中文相关性不佳。上游不是额外的Agent工具，均由SearXNG聚合。
- Wikipedia信息卡转换为同样的标题/链接/摘要返回模型，避免只读取results而遗漏百科内容；通用搜索结果按URL去重。
- 后端环境变量 `PONYCHAT_SEARXNG_URL` 可覆盖地址；默认本机上述端口。工具参数不接收地址、账号或密钥。
- 根据查询词本身搜索，固定 `language=all`。部署实测 Google 的 zh-CN/en 筛选返回空结果，因此不向模型开放语言筛选参数。
- 每轮最多 3 次搜索，计入 Harness 原有 8 次总工具预算；进程内最多 2 个并发请求，单次含排队最多 18 秒，返回最多 6 个去重的公开 HTTP(S) 链接。
- 返回 provider、query、status、searched_at、results 和失败引擎；结果含标题、链接、摘要、可用的原始发布时间。检索时间不等于发布时间。
- 明确区分 success、partial、no_results、unavailable、timeout、rate_limited、invalid_response、budget_exhausted；不回退到 Qwen、Grok、其他搜索 API 或模型知识。
- 图片识别仍使用 `force_web=False`，不能通过图片工具绕开唯一联网来源。
- 搜索只发必要关键词，网页资料不作为指令或私人记忆证据。只搜索摘要，不声称读取过页面全文。

## 每轮自动注入摘要

`prepare_autonomous_request` 在记忆开启时读取统一记忆库，将 `calendar_memory` 直接放入本轮模型输入，不依赖 Agent 先调用检索工具。

以 Asia/Shanghai 时间为准，周一开始一周：

| 层级 | 注入范围 |
| --- | --- |
| daily | 本周周一至今天，每一天的摘要 |
| weekly | 本月1日至今天涉及的各个 ISO 自然周，包括跨月周 |
| monthly | 本年1月至当前月，每个月的摘要 |
| annual | 所有已存在且有效的年度摘要，包括已有的本年摘要 |

例如2026-09-06：日摘要范围为08-31到09-06，周摘要为2026-W36，月摘要为2026-01到2026-09，年度层读取全部已有年份。未来日期不预填。

摘要内容完整注入，不做 top-k 或字符截断。保留 entry_id、version、source_ref、原文来源、更新时间、确定性、周期是否进行中。按用户、角色、重置世代隔离；隐藏/编辑/删除来源造成的失效内容不进入上下文。记忆关闭时不注入。

缺失或失效的日/周/月摘要标记 missing；这不等于没有发生。已有后台整理机制继续负责生成摘要，本次不在每轮聊天前同步重算历史，也不将旧库未核验摘要直接作为事实。更细的历史和事实仍可按需检索。年度摘要不受条数上限限制，长期使用时输入 Token 会相应增长。

## 运维与验收

部署入口：`scripts/ops/deploy_searxng.py`。停止/恢复搜索可使用 `systemctl stop/start ponychat-searxng.service`，配置和源码保留。健康检查 `/healthz`；私有服务不开放公网端口。

搜索验收：用实际普通对话工具分别查询“紫悦”和“Twilight Sparkle”，保留工具原始 JSON。`PONYCHAT_SMOKE_SEARCH=1` 启用已有隔离数据库 HTTP /api/chat 验收中的双查询检查，真实调用 Harness 和 SearXNG，同时检查消息保存、记忆提交、用量和鉴权；不登录或修改生产用户数据。
